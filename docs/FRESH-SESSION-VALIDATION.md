# 새 세션 실증 절차 — 짧은 요청 하나로 검증하기

바뀐 구조가 실제로 작동하는지는 **평소와 같은 짧은 요청과 기사 URL만 받은 새 세션**에서 확인한다. 이 문서는 그 실증의 절차·기록·평가 항목을 정한다. 이 문서를 쓰는 작업에서는 실증을 실행하지 않는다.

## 왜 코드 검사만으로는 부족한가

lint·check:all·시작/재개 테스트·재현 해시는 구조가 깨지지 않았음을 보인다. 짧은 요청을 받은 제작자가 기사에 맞는 장면을 고르고 실제로 움직이는 한 편을 만드는지는 보이지 않는다. 그 판단에는 실제 제작 실행이 필요하다. 먼저 첫 핵심 장면까지만 확인하고 중단하는 저비용 시험을 수행한다. 이 문서 작성 중에는 자동으로 제작을 시작하지 않는다.

## 우선 실행: 같은 요청, 첫 핵심 장면에서 중단

전체 기사 완성은 첫 시험의 필수 범위가 아니다. 새 세션에 아래의 평소 요청 한 줄만 전달하고 제작을 시작한다. 테스트 진행자는 제작자에게 원하는 장면·도구·모션을 지정하지 않는다.

1. 제작자가 기사 전체의 맥락과 이야기 가설을 파악하고 핵심 설명 장면을 스스로 선택한다.
2. 제작자는 정상 제작 지침에 따라 그 장면의 실제 배경·자막 영역을 포함한 합성 이미지와, 동작이 핵심인 경우 짧은 동작 시안을 만든다.
3. **테스트 진행 측이 외부에서** 첫 핵심 합성 시안의 scene_proof 기록을 읽기 전용으로 관찰한다. 필요한 이미지·동작 시안이 준비되면 세션을 중단/일시정지하고 그때까지의 결과를 평가한다. 기사 전체 음성·최종 렌더까지 계속 기다리지 않는다. 중단은 실행 제어이며 장면별 정답 피드백이 아니다.
4. 초기 확인을 건너뛰고 전체 구현이나 TTS로 직행한다면 그것 자체를 절차 실패로 기록하고 중단한다. 부족한 설계나 생성 선택을 테스트 도중 코칭해 통과시키지 않는다.
5. 통과한 뒤에만 전체 제작 시험으로 이야기·장면 연결·음향·최종 검수를 확인한다. 실패하면 구조를 수정한 뒤 다시 **새 세션**에서 같은 짧은 요청으로 시작한다.

중단 시점과 이미 시작된 외부 호출을 기록한다. 호출 취소 가능 여부는 도구에 따르며, 이미 발생한 비용까지 없다고 보고하지 않는다. 이 시험에도 기사 파악·자료 확보 비용은 들지만 전체 렌더와 전편 수정 비용은 줄일 수 있다.

이 결과는 **새 세션의 진입과 첫 핵심 장면 검증**이다. 기사 전체 완성 품질이나 전 구간의 표현 다양성을 통과했다고 보고하지 않는다. 만약 사용자 요청 자체를 '8초 장면 하나 만들어줘'로 바꿔 시험했다면, 유용한 부분 제작 시험이지만 원래의 짧은 전체 제작 요청과 같은 조건의 회귀 시험은 아니다.

## 두 종류의 시험을 분리한다

| | A. 기존 기사 · 새 세션 회귀 | B. 미열람 기사 일반화 |
|---|---|---|
| 기사 | `https://www.hani.co.kr/arti/science/science_general/1278983.html` (은하 회전) | 사용자가 그때 고른 실제 기사 |
| 묻는 것 | 이미 다뤄 본 기사에서 새 구조가 이전보다 나아졌는가 | 처음 보는 기사에서도 같은 품질이 나오는가 |
| 한계 | 이 기사는 개발 과정에서 이미 열람·논의됐다. 일반화 증거가 아니다 | 순서상 A 다음. A 통과가 B를 대신하지 않는다 |

**B용 URL은 이 문서가 만들지 않는다.** 실증 시점에 사용자가 지정한다. 존재를 확인하지 않은 기사 주소를 예시로라도 적지 않는다.

A의 비교 대상에 대한 사실: 이 저장소의 수록 예시 N44는 **다른 기사**(`.../1278434.html`)다. 1278983으로 만든 완성본은 이 저장소에 없다. 따라서 A는 "저장소의 기존 납품본과 나란히 비교"가 아니라 "개발 중 관찰했던 결과와의 비교"이며, 그 이전 관찰 기록은 평가자가 별도로 제시한다. 없으면 A도 단독 관찰로 기록한다.

## 제작 세션에 주는 것 / 주지 않는 것

주는 것: 최종 커밋의 clean checkout(`git lfs pull` → `npm ci` → `npm run setup:hooks`), 프로젝트 스킬·config·공통 표현 레퍼런스, 평소 쓰는 도구와 계정, 아래 한 줄짜리 요청.

주지 않는 것: 이 대화와 그 요약, 이전 세션의 연속, 전역 메모리, 평가 항목표, 이번 편에 맞춘 샷·연출 지시, 이번 시험 기사의 이전 제작 데이터·장면 코드·결과물 및 다른 작업 트리. 납품 프로젝트에 원래 포함된 공식 예시는 정상 입력으로 유지한다.

**checkout이나 worktree를 새로 만든 것은 문맥 분리가 아니다.** 호스트가 전역 지침·메모리·이전 대화 요약을 자동 주입하면 그 세션은 blind가 아니다. 세션에 실제로 주입된 목록을 확인해 기록하고, 확인할 수 없으면 "확인 불가"로 적는다. 이전 기억에 접근 가능한 세션을 blind라고 표기하지 않는다.

납품 저장소에 원래 포함된 N44 예시와 세 공통 레퍼런스는 그대로 둔다. 이것을 지우면 평소 납품 환경과 다른 시험이 된다. 허용된 예시 목록과 열람 범위를 기록하되, 시험 기사 1278983의 이전 제작 워크트리와 이 대화는 제공하지 않는다. 동일 호스트에서 다른 작업 트리에 접근할 수 있다면 작업 디렉터리만 바꾸지 말고 접근 범위를 분리한 환경을 사용한다. 실제 격리 범위를 확인하지 못하면 그 한계를 기록한다.

## 세션에 보내는 정확한 문장

```
이 기사로 숏폼 만들어줘. https://www.hani.co.kr/arti/science/science_general/1278983.html
```

이 한 줄만 보낸다. 분량·샷 수·모션 개수·스타일·도구·검수 절차를 덧붙이지 않는다. 새 권한 단계·할당량·고정 템플릿도 추가하지 않는다 — 평소 절차 그대로 돈다. 기존 기본값과 위임으로 해결할 수 있는 항목을 반복 질문하면 기록한다. 실제로 필요한 질문에 답할 때도 과거 편이나 평가 항목을 알려주지 않는다. 주고받은 모든 문장을 원문 그대로 남긴다.

## 기록 (실증 시작 전에 형식을 확정한다)

`docs/research/<날짜>-fresh-session/`에 raw·summary·index로 남긴다.

1. 커밋 SHA, checkout 절대경로, `git status` clean 여부, `git lfs pull` 결과, 기본 수록 예시와 공통 레퍼런스 버전.
2. 호스트·모델·세션 식별자, 세션에 자동 주입된 지침·메모리·요약의 실제 목록(또는 "확인 불가").
3. 사용자 쪽에서 보낸 모든 메시지 원문과 시각.
4. 제작자가 실행한 명령, 호출한 외부 도구, 도구 실패 응답 원문.
5. 사람이 답하거나 대신 고친 지점 전부 — 힌트 한 줄도 개입으로 센다.

## 평가자가 따로 확인하는 것

제작 세션에는 이 표를 주지 않는다. 각 항목은 통과·불통·판단 불가로 적고, 판단 불가를 통과로 집계하지 않는다.

| # | 항목 | 확인 기준 |
|---|---|---|
| 1 | 기사에 근거한 시각 | 화면의 대상·수치·장소가 이 기사에서 나오는가. 일반 우주 이미지로 대체하지 않았는가 |
| 2 | 내레이션이 말하는 동작 | 말로 설명한 동작이 그 구간 화면에서 실제로 일어나는가 |
| 3 | 생성 모션의 적합한 사용 | 필요한 자리에 썼는가. **개수 목표를 두지 않는다** — 안 쓴 선택도 이유가 타당하면 통과 |
| 4 | 불필요한 텍스트 | 고정 나레이션 자막 외에 같은 설명을 중복하는 문구·장식 라벨·읽히지 않는 글자가 있는가 |
| 5 | 배경과 자막 | 배경이 내용을 밀어내지 않는가. 자막 가독성과 안전영역(좌우 80px·상하 100px) |
| 6 | 실제 움직임 | 정지 이미지 나열이 아닌가. 팬·줌이 내용과 맞는가 |
| 7 | 전체 이야기 | 처음부터 끝까지 이어 보고 들었을 때 한 편으로 성립하는가 |
| 8 | 한계의 정직성 | 도구 실패·미검수·불가능을 사실대로 말했는가. 보거나 듣지 못한 것을 검수 완료로 적지 않았는가 |

7과 8은 파일 존재나 렌더 성공으로 대신할 수 없다. 실제 연속 시청·청취를 했는지, 못 했으면 못 했다고 적혀 있는지를 본다.

## 이 문서가 하지 않는 것

실제 제작을 실행하지 않는다. 해당 기사의 내용을 외부에서 확인하지 않았다 — 위 URL은 기존 제작 기록에서 확인한 시험 후보 주소다. B용 기사 주소를 만들어 내지 않는다. 기존 절차에 없던 권한·비용·양식을 새로 요구하지 않는다.
