# 제작 영상 목록

목적은 어떤 기사로 언제 만든 영상인지 한눈에 찾고, 바로 확인·다운로드하는 것이다. 제작자와 한겨레 담당자가 함께 쓸 결과물 조회 화면이며 실험 과정이나 버전 비교 화면이 아니다.

## 열기

권장: `npm run videos:serve` → `http://127.0.0.1:4381/videos.html`. 로컬 서버를 켜 두면 새로고침할 때 목록이 갱신되고 영상 다운로드가 첨부 파일로 동작한다. 목록에 등재된 미디어만 제공하며 저장소 전체를 공개하지 않는다.

`npm run videos` → `out/videos.html`. 브라우저에서 직접 열 수 있는 독립 HTML이다. 다만 `file://`로 열면 브라우저에 따라 다운로드 버튼이 저장 대신 영상 파일을 열 수 있으므로 다운로드까지 사용할 때는 로컬 서버를 사용한다. 영상 파일은 상대경로로 연결된다. `npm run gallery`도 같은 화면을 만들며 `out/gallery.html`은 새 주소로 이동한다.

현재는 로컬용이다. 한겨레 공유 서버·저장소는 아직 정해지지 않았다. HTML만 전송하면 영상이 따라가지 않는다. 공유 환경이 정해지면 영상과 썸네일을 함께 배포하고 `src`·`poster`를 접근 가능한 주소로 연결해야 한다.

## 파일 위치 찾기

경로는 모두 클론한 프로젝트 폴더를 기준으로 한다. 영상 목록에서는 **영상 클릭 → 더보기 → 저장 폴더 열기**가 가장 빠르다. 다른 프로그램에서 파일을 사용할 때는 같은 메뉴의 **파일 위치 복사**를 쓴다.

```text
프로젝트 폴더/
├─ README.md                              사용 진입 안내
├─ docs/PRODUCTION_PROMPT.md               제작 요청 프롬프트 정본 — 프롬프트 탭이 읽는다
├─ docs/VIDEO-LIBRARY.md                   이 안내 문서
└─ out/
   ├─ videos.html                         자동 생성된 영상 목록
   └─ pilots/<기사 ID>/deliver/<버전>/
      ├─ <기사 ID>_<버전>.mp4              완성 영상
      └─ cover.png                        썸네일 예시 — 있는 경우
```

`out/videos.html`은 직접 편집하거나 이동하지 않는다. 완성본도 등록된 위치에 보관해야 재생·다운로드 링크가 유지된다. 클론만으로는 Git에서 제외된 `out/`의 영상과 이미지가 복사되지 않는다. 이미 만들어진 영상을 넘겨받을 때는 등록된 폴더 구조를 유지해 함께 전달받는다.

## 표시 규칙

- `pilot.json.status === "delivered"`이고 대표 영상 파일이 실제 존재하는 편만 표시한다. `review`·작업 중·보관 편과 실험 원장은 제외한다.
- `deliver/LATEST`에 대응하는 등록 버전을 우선하고, 링크가 없거나 등록 버전과 대응하지 않으면 `versions`의 마지막 파일 경로를 사용한다. 대표 파일이 유실됐으면 이전 파일로 바꾸지 않고 목록에서 제외하며 생성 명령에 경고한다.
- 제작 완료일은 대표 버전의 `completed_at`(선택) → 편의 `delivered` 순서다. 이전 편의 `delivered`는 편 수준의 기록이며, 후속 수정본의 제작 시각까지 증명하지 않는다. 새 수정본에는 `completed_at`에 완료 날짜를 기록한다. 값이 없으면 ‘날짜 미등록’이며 날짜 필터 적용 시 제외한다. 착수일·기사 발행일·파일 수정일은 완료일로 사용하지 않는다.
- 기사 원제·기자·발행일은 보존된 원문 JSON을 읽는다. 원문은 수정하지 않는다.
- 실행 대상 체크아웃을 우선하고, 없는 편과 미디어는 Git에 등록된 다른 워크트리에서 보충한다. 기존 편의 메타데이터는 임의로 다른 브랜치의 것으로 교체하지 않는다.
- 이미지가 있으면 썸네일로 사용하고, 없으면 실제 영상 앞부분을 작은 미리보기로 표시한다.

## 검색과 영상 확인

제작 완료일별 목록에서 영상 제목·원문·기자·기사 발행일을 함께 확인한다. 검색은 영상 제목·기사 제목·기자·한겨레 기사 URL·기사 번호에 즉시 적용된다. `https://www.hani.co.kr/arti/science/science_general/1273728.html` 같은 링크 전체나 `1273728`만 붙여 넣어도 해당 영상을 찾는다. 제작일 버튼에서 최근 7일·30일 또는 직접 날짜 범위를 선택한다. 최신순·오래된순·제목순 정렬을 제공한다.

썸네일·제목·재생 아이콘을 누르면 상세 창이 열린다. 현재 결과 안에서 이전·다음 영상을 이동하며 원문과 파일 정보를 확인하고 다운로드할 수 있다. 모바일은 세로 배치이며 상세 창 상단의 닫기·이동 버튼은 스크롤 중에도 유지된다.

## 제작 프롬프트 탭

상단 탭에서 **제작 프롬프트**(`videos.html#prompt`)를 열면 새 기사 한 편을 요청할 때 쓰는 프롬프트를 그대로 읽고 복사할 수 있다. 영상 목록 화면(`#main`)과 같은 파일 안에 있어 이 페이지만 열어도 확인·사용이 끝난다.

- 본문의 정본은 `docs/PRODUCTION_PROMPT.md`의 ```text 블록이다. 화면은 이 파일을 **읽기만** 하며, 프롬프트를 고칠 때는 문서를 고치고 `npm run videos`로 목록을 다시 생성한다. 화면에서 입력한 내용은 문서에 반영되지 않는다.
- 기사 주소 칸에 URL을 넣으면 프롬프트 마지막 줄의 `[URL]` 자리에 즉시 들어간다. 비워 두면 `[URL]` 그대로 복사된다.
- 「프롬프트 복사」는 화면에 보이는 내용을 그대로 클립보드에 넣는다. 클립보드 사용이 막힌 환경(`file://` 등)에서는 본문을 선택 상태로 돌려주고 직접 복사하도록 안내한다.
- 본문을 직접 고치면 기사 주소 자동 채움을 멈춘다. 「원래대로」를 누르면 문서 원본으로 되돌린다.
- 문서를 찾지 못하거나 ```text 블록이 없으면 화면에 사유를 표시하고, `npm run videos` 실행 시에도 경고로 알린다.

## 파일 다운로드와 위치

다운로드 메뉴에서 영상+썸네일 묶음, 영상만, 썸네일만 받기를 선택한다. 썸네일 한 장은 이미지로, 여러 장은 ZIP으로 제공한다. 상세 화면의 이미지를 누르면 원본 비율로 크게 보고 한 장씩 받을 수 있다.

썸네일은 `pilot.json.thumbnails.candidates[]`에서 `status: "approved"`로 확정한 파일을 우선한다. 해당 편의 `out/pilots/<id>/` 아래에 있으면 영상과 다른 폴더에 있어도 대표 이미지·상세 화면·다운로드에 함께 반영한다. 여러 장을 확정했다면 등록 순서의 첫 장을 대표 이미지로 사용한다. 확정 파일이 유실됐으면 생성 명령에 경고하며 예전 커버로 조용히 되돌리지 않는다.

확정 기록이 없는 이전 편은 대표 영상과 같은 완성본 폴더의 `cover.*`, `thumbnail.*`, `커버.*`, `썸네일_A.png` 같은 한글 이름, `cover-name.*`, `thumbnail_name.*`, `A.png` 같은 한 글자 시안 파일과 `B-r2.png` 같은 수정 파일을 읽는다(PNG/JPG/JPEG/WebP). 별도 작업 폴더의 미확정 후보나 임의 검토 이미지는 다운로드 대상으로 삼지 않는다. 해당 이미지가 없으면 ‘썸네일 미등록’으로 표시하며 영상 프레임을 게시용 이미지로 자동 생성하지 않는다.

상세 화면의 더보기에는 저장 폴더 열기와 파일 위치 복사가 있다. 폴더는 실제 대표 MP4가 있는 위치이며 다른 워크트리에 보관된 경우 그 위치로 열린다. 클립보드 사용이 불가능하면 경로를 선택해 직접 복사할 수 있다.

ZIP과 파일 위치 기능은 `npm run videos:serve`로 연 로컬 화면에서 제공한다. HTML 직접 열기에서는 개별 파일 링크를 제공하고 로컬 작업 메뉴를 숨긴다. ZIP 안의 한글 등 비 ASCII 파일명은 압축 프로그램 간 호환을 위해 영문 기사 ID와 번호로 바꾼다. 원본 파일과 개별 이미지 다운로드의 이름은 유지한다. ZIP에는 대표 MP4와 썸네일만 포함되며, 영상 마스터·원문·기타 부속 파일은 포함하지 않는다. 운영 시스템의 `zip` 명령으로 재압축 없이 전송하며, 파일 관리자는 macOS `open`, Windows `explorer.exe`, Linux `xdg-open`을 사용한다. 현재 실물 검증은 macOS에서 수행했다.

## 자동 갱신

**완성본 등록 → 목록 생성 → 열린 화면 새로고침** 순서다. 생성된 HTML을 수동으로 고칠 필요는 없다. 영상 파일이 있다는 사실만으로 작업 중 영상을 완성본으로 취급하지 않는다.

- `npm run pilots`: 편 상태를 대장에 반영한 후 목록을 생성한다. `--check`는 기존처럼 읽기 전용이다.
- `npm run out:deliver -- <id> --yes`: 파일 복사·대장·LATEST 갱신이 끝난 후 현재 및 주 작업트리 목록을 생성한다. 예행에서는 생성하지 않는다.
- 썸네일 확정: 제작 에이전트가 상세 기록과 `pilot.json`에 `approved`를 반영하고 `npm run videos`로 목록까지 갱신한다. 사용자가 여는 주 작업트리에서도 실행한다. `file://` HTML은 생성 시점의 정적 목록이므로 파일을 다시 생성한 뒤 열린 화면을 새로고침해야 한다. 로컬 서버는 새로고침 요청 때 확정 기록을 읽는다.
- JSON이나 MP4를 수동으로 고치기만 하면 자동 실행되지는 않는다. `npm run videos` 또는 기존 완료 등록 명령을 실행한다. 이미 열린 브라우저는 새로고침해야 한다.

### 만든 영상이 목록에 보이지 않을 때

1. 먼저 브라우저를 새로고침한다. 로컬 서버는 요청 시점의 파일과 등록 정보를 다시 읽는다.
2. 제작 절차에서 해당 편이 완료 상태(`delivered`)로 등록됐는지 확인한다. `out:deliver`는 파일 정리와 목록 갱신을 수행하며, 편의 상태를 자동으로 `delivered`로 바꾸지는 않는다.
3. 해당 편에 등록된 대표 MP4가 실제 경로에 있는지 확인한다. 파일이 빠졌다면 같은 위치에 복구해야 한다. 생성 명령의 경고에도 누락 정보가 나온다.
4. 등록 정보를 수동 수정했다면 `npm run videos`로 목록을 다시 생성한다. 열린 화면도 새로고침한다.

## 구현 및 검증

수집은 `scripts/lib/video-library.mjs`, 화면은 `scripts/templates/video-library/`, CLI는 `scripts/build-video-library.mjs`다. 별도 프레임워크·의존성·외부 CDN은 없다.

`npm run videos:test`는 완성 상태 선별, 대표본 선택과 유실, 날짜 출처, 워크트리 경로, 원문 보존, HTML 데이터 삽입 안전성, 제작 프롬프트 적재와 누락 경고를 검증한다.

화면의 색상·글자·간격·버튼·반응형 규칙은 디자인 규칙 (과거 내부 기록·로컬 보관)에 정리했다.
