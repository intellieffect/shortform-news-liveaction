# 발화·화면 제작 연결 변경

## 문제와 범위

사용자 지시 원문:

> 구조를 수정 진행해. 그리고 검증은 새로운 세션에서 원래는 기사 url 을 주고 이 url 숏폼 만들라고만 했어. 제대로 테스트하려면 동일하게 새로운 세션에서 해야하며 어떤 걸 만들어보라고 간단하면서도 기존의 컨텍스트 없이 새로운 환경에서 제대로 실행되는지 테스트해볼 수 있을까?

나레이션의 동작이 라벨·화살표로 대체되고 생성이 배경 이미지에 머무르는 문제를 줄이기 위해, 새 제작의 설계·실물·생성·검수 연결을 바꾼다. 고정 장면 템플릿이나 생성 할당량은 도입하지 않는다. 기존 완성본은 수정하지 않는다.

## 구현 범위

- 새 start의 visual-explanation@1: 기존 concepts 안의 목적·핵심 설명 구간·구현 재료, 실제 화면 문구. generation_jobs와 채택 자산 연결.
- 음성/timeline 이전의 scene_proof: 실제 시안과 관찰 원문을 입력 해시와 연결. 자산/합성, 이미지/동작, 미확인/수정/사용 가능을 구분. 변경 후 stale.
- 화면 글자: 선언 원문을 렌더하는 EditorialScreenText. 문구와 동시 자막의 중복 및 JSX 직접 문구 진단. 스타일 고정 없음.
- resume/intent: 미확인 핵심 장면·미채택 생성·문구 문제를 작업 문맥으로 제공. experience에는 계획 미노출.
- final visual review: 핵심 설명별 실제 대상·작용·결과·텍스트 의존 관찰. 코드 추론/미확인을 pass로 기록하지 못함. 기존 전체 이야기·청취 검수 유지.
- [새 세션 실증 절차](FRESH-SESSION-VALIDATION.md): 평소의 URL+짧은 요청만 사용. 같은 요청으로 시작하고 첫 핵심 시안에서 외부 중단하는 저비용 시험을 우선한다. 기존 기사 회귀와 미열람 기사 일반화를 구분.

## 기술 검증과 한계

`npm run visual-production:test`는 임시 저장소에서 실제 start/begin/finish/resume/review-input과 ffprobe를 실행한다. 의도적 결함(설명 누락·잘못된 발화 연결·문구 누락·입력/출력 변조·PNG의 동작 시안 위장·생성 연결 누락·코드 추론 pass)을 넣어 탐지한다. 테스트용 색상 이미지/영상은 품질 시안이 아니다. 기존 production:entry:test, references:test, unified:test, lint, check:all로 호환성을 확인한다. 검사 실행 결과는 이번 변경의 납품 보고에서 별도로 보고한다.

필드 채움과 usable 관찰은 미술·설명 성공의 자동 증명이 아니다. source 진단은 동적 문자열·미디어 속 글자·실제 노출 면적을 전부 검사하지 못한다. 초기 proof의 stale은 보수적으로 편의 공통 입력 변경에도 발생한다. 외부 생성 도구는 제작 에이전트가 실제 연결과 사용자 위임 범위 안에서 실행하며 이 엔진은 도구를 호출했다고 꾸미지 않는다.

새 세션의 실제 기사 제작은 별도 실행이다. 코드 테스트 통과로 그 품질을 입증했다고 보고하지 않는다. 독립 검수자의 관찰 선언이 진실인지까지 코드가 증명하지 못한다.


검증 결과(이번 변경): visual-production 15건, production-entry 19건, references 7건, unified 7건 통과. lint 통과. check:all은 활성 N44 1편 ERROR 0(기존 registry 경고 13), staged 공유 검사 오류 0. 전체 과거 편 검사와 새 기사 제작은 이 범위에 포함하지 않는다. Opus 독립 코드 리뷰의 단일 프레임 영상·시간 기준·계약 삭제·공통 JSX·경로 문제를 보완하고 회귀 테스트했다. 초기 시안 누락과 텍스트 진단을 무조건 최종 차단하는 제안은 채택하지 않았다. 초기 절차는 새 세션 시험에서, 최종 문구·설명 적합성은 실제 표본을 요구하는 독립 검수에서 판단한다.
