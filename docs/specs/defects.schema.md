# defects.json — 결함 장부 스키마

`docs/defects.json` 은 편 1~8 이후 모든 편의 **품질 결함 전수 장부**다. 채점은 `npm run eval:defects`(check:all 에 편입). 원 행은 고치지 않는다 — 정정은 새 행 append(원문 보존).

## 행 필드

| 필드 | 뜻 | 규칙 |
|---|---|---|
| `id` | `p<편번호>-<연번>` | 재부여 금지(커밋 뒤부터) |
| `pilot` / `beat` | 편 id · 비트(`b07`) | 비트 특정 안 되면 빈 문자열 |
| `summary` | 결함 한 문장 | 무엇이 어떻게 잘못됐나 |
| `found_by` | `human` · `main` · `input` · `agent:<이름>` · `guard:<코드>` · `대조군` | **사람 최초 발견 수가 품질 지표** |
| `found_at` | 발견 시점(문서의 표현) | `should_catch_at` 과 서열 비교 → 하류 유출 |
| `should_catch_at` | 원래 걸렸어야 할 단계 | 근거 없으면 빈 문자열 — **추측 금지** |
| `cause` | 원인(G코드 등) | |
| `guard` | 지금 이 결함류를 잡는 가드 코드 | 채점기가 scripts/ 실물과 대조(유령 검출). 빈 값 = **승격 대기 백로그** |
| `fixed_in` | 고쳐진 판/커밋, 미수정 `open` | |
| `evidence` | 문서 원문 인용 ≤200자 | 의역 금지 |
| `source` | repo 상대 경로 · `git:<hash>` | 미머지 편은 ` @<branch>` 접미 |
| `decision_ref` | 게이트 원장 역참조 `<편id>#L<행>:<row_id\|free>` | to-defects 변환행에만 — 재변환 dedup 키, 지우면 중복 행 재생성 |

## 수록 기준 (2026-09-04 확정)

- **수록**: 렌더 화면·자막·소리·데이터가 기준(기사 사실·가독·규칙)에 어긋나 고쳤거나 고쳤어야 했던 것. 검토 라운드 이슈, 사후 발견, 소급 실측 적발 전부.
- **제외**: git·파일 유실 등 프로세스 사고(별도 incident 문서) · 단순 개선 아이디어 · 클라이언트 확인 대기 항목.
- **후보 기각**: 채택 전 후보 선별은 원칙 제외, 단 **비가역 비용이 발생한 건(생성 크레딧 소모 등)은 수록**.

## 알려진 한계 (숫자 읽을 때 주의)

- `should_catch_at` 은 문서 근거가 있는 행만 채워져 있다 — **하류 유출 수는 하한값**이다.
- 6편(대조군)은 발견 주체가 문서에 명시돼 있지 않아 다수가 `main` 으로 기재 — 6편 「사람최초 0」은 과소집계다.
- 편5 「v1 검토 13건」(summary.md) vs 실물 17건(raw.md) 처럼 원문서끼리 셈이 다른 곳은 **실물 목록 기준**으로 실었다.
- 초기 편(1·2)에는 에이전트 체계가 없어 `agent:*` 0 이 정상이다.
