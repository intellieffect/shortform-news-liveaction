# 설명·정보 디자인 검수 보완

사실·읽힘·설명력·조형 완성도를 각각 판단한다. 사실이 맞고 문자가 읽힌다는 이유로 설명·조형까지 통과시키지 않는다. 아래 완성도 기준은 전체 시안에서 적용한다. 선택적 표현 시험에는 시험 질문에 필요한 범위만 적용하며, 모든 항목을 음성 전 승인 조건으로 삼지 않는다.

- 핵심 발화마다 화면의 대상·작용·결과가 무엇인지 확인한다. 과정은 같은 물질/대상의 변화가 읽혀야 하며, 문구 등장이나 코드 모션 존재만으로 충족하지 않는다.
- 수치·비교에는 대상과 기준, 정의에는 용어가 가리키는 영역/관계, 인용에는 귀속과 필요한 맥락을 연결한다. 표·도해·그래픽은 필요한 경우에 선택하며 전부 넣는 체크리스트로 만들지 않는다.
- 핵심 설명이 작고 약한 입자나 반복 장식에 묻히는지, 주석이 주인공보다 먼저 읽히는지 모바일에서 확인한다. 필요한 조건·출처는 보존한다.
- 외형 자산 선택이 실제로 불확실하면 확정 전에 그 구간을 장면으로 시험한다. 이 시험은 선택이며 음성 착수 게이트가 아니다([초기 첫 장면](review-loop.md#초기-첫-장면)). 이미 완성된 모형이 전후 변화를 막으면 자산·구도·구현부터 바꾼다.

이미지·일러스트·오버레이는 [시각 표현 안내](visual-expression.md)를 참고해 실제 배경 위의 형태·가장자리·크기·색과 질감·가림·타이포·모션이 어울리는지 본다. 설명뿐 아니라 분위기·리듬·강조·시각적 재미에 기여하는 표현도 인정한다. 사용량·등장 간격·필수 표현 종류를 채점하거나 미사용 사유를 요구하지 않는다. 연속 구간에서 내레이션·자막·배경과 함께 느껴지는 이해·몰입을 관찰하며, 생성 도구나 스타일 준수만으로 완성도를 통과시키지 않는다.

첫 전체 시안이 나오면 제작자는 지정된 독립 shot-judge와 fact-check를 **한 메시지에서 병렬로** 호출하고 실물 관찰→의도 대조→수정→재검수를 이어간다. 판단의 근거가 되는 원문을 보존한다. 핵심 과정/관계가 이해되지 않는 결함은 blocking으로 다룬다. 관찰된 결함을 코드에 움직임이 있다는 이유만으로 해소하지 않는다.

연속 시청과 실제 청취를 프레임 추출·전사·디코드·음량 측정과 구분한다. 확인 수단이 없으면 incomplete로 남기고 시안과 함께 한계를 보고한다. 별도 사용자 승인 관문은 추가하지 않는다. 새 제작의 실제 설명 관찰은 [발화→화면 제작](visual-production.md)의 explanations로 연결한다. 보고서와 수정 이력은 기존 review-loop.md 계약을 따른다.

공통 세트 비교는 [표현 레퍼런스 활용](visual-references.md)에 따른다. 먼저 이번 시안 자체를 관찰한 뒤 intent에서 동일한 기준 세트와 대조한다. 장면 유형 일치·외형 유사도가 아니라 설명·합성·위계·발화와 움직임의 연결을 보고, 전체 영상의 이야기와 호흡은 별도로 검토한다.

사례에서 가져온 구도·색·도형·배치·등장 순서가 이번 대상·자료·관계에도 적합한지 확인한다. 특히 대상·값·관계가 수정된 장면은 남은 표현이 실제로 전달하는 내용을 다시 본다. 사례와 닮았다는 이유만으로 결함을 판정하거나, 사례의 형태를 재현했다는 이유로 설명 성공을 인정하지 않는다. 이번 화면에 맡긴 관계가 전달되지 않으면 사실·가독성·외형 완성도와 구별하여 기존 설명 검수의 문제로 남기고 수정·재확인한다.
