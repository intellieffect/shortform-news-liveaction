# 설명·정보 디자인 검수 보완

사실·읽힘·설명력·조형 완성도를 각각 판단한다. 사실이 맞고 문자가 읽힌다는 이유로 설명·조형까지 통과시키지 않는다.

- 핵심 발화마다 화면의 대상·작용·결과가 무엇인지 확인한다. 과정은 같은 물질/대상의 변화가 읽혀야 하며, 문구 등장이나 코드 모션 존재만으로 충족하지 않는다.
- 수치·비교에는 대상과 기준, 정의에는 용어가 가리키는 영역/관계, 인용에는 귀속과 필요한 맥락을 연결한다. 표·도해·그래픽은 필요한 경우에 선택하며 전부 넣는 체크리스트로 만들지 않는다.
- 핵심 설명이 작고 약한 입자나 반복 장식에 묻히는지, 주석이 주인공보다 먼저 읽히는지 모바일에서 확인한다. 필요한 조건·출처는 보존한다.
- 외형 자산을 확정하기 전에 위험한 설명 구간을 실제 장면으로 확인한다. 이미 완성된 모형이 전후 변화를 막으면 자산·구도·구현부터 바꾼다.

첫 전체 시안이 나오면 제작자는 지정된 독립 shot-judge와 fact-check를 호출하고 실물 관찰→의도 대조→수정→재검수를 이어간다. 판단의 근거가 되는 원문을 보존한다. 핵심 과정/관계가 이해되지 않는 결함은 blocking으로 다룬다. 관찰된 결함을 코드에 움직임이 있다는 이유만으로 해소하지 않는다.

연속 시청과 실제 청취를 프레임 추출·전사·디코드·음량 측정과 구분한다. 확인 수단이 없으면 incomplete로 남기고 시안과 함께 한계를 보고한다. 새 JSON 필드나 별도 사용자 승인 관문은 추가하지 않는다. 보고서와 수정 이력은 기존 review-loop.md 계약을 따른다.
