# 사람 게이트 ①~⑦ — 제시·응답·기록 규격

## `editorial-concept@1`에서의 적용

이 문서의 7회 게이트는 `script-faithful@1`의 상세 규격으로 보존한다. `editorial-concept@1`에서는 이미 위임된 원고·자료·도해·보이스·음향 선택과 3′/4-3R 수정은 제작자와 독립 검수자가 내부에서 닫는다. 사용자는 다음 경우에만 본다.

- 목표·논조·브랜드나 제공 대본 잠금 범위가 바뀌는 선택
- 사용 권리 또는 사실 해석이 불명확한 선택
- 새 유료 생성·TTS처럼 승인된 비용 범위를 넘는 선택
- 독립 검수와 수정까지 끝난 완성 시안의 최종 판단

사용자 제출물은 완성 영상, 중요한 변경과 이유, 남은 선택의 구체적 대안이다. 명확한 겹침·누락·오인·타이밍 결함을 건별 승인받지 않는다. 상세는 [review-loop.md](review-loop.md).

사람 판정 7자리의 **제시 형식·응답 문법·기록 방법**. 근거는 7편치 판정 사건 88건 채굴 + 설계 3안 + 적대 비평 16건 — `docs/research/2026-09-04-eval-harness/` (과거 내부 기록·로컬 보관) (gates-spec.md · gate-design-raw.json). 2026-09-04 사용자 승인.

## 왜 형식이 규칙인가 — 실측 셋

- **제시 형식이 판정 속도를 지배한다.** 원고 게이트 대기 94분(6편, 근거 없는 문답) → 1~2분(7편, 비교표 동봉).
- **틀린 전제가 내용 오류보다 비싸다.** G10 — main 이 판정을 「크기 문제」로 고쳐 적어 옳은 선택지가 표에 없었고 결함이 납품본까지 갔다.
- **사람 판정은 산문 한 문장으로 온다.** 구조화 응답을 강제하면 게이트가 느려진다 — 기록은 main 몫이다.

## 공통 원칙 6

1. **도착 시 완결 패키지.** 사람이 기다리며 추가 자료를 요청하면 그 게이트 형식은 실패다.
2. **증거 해상도 = 판정 해상도.** 가독은 원해상 크롭(`npm run qa:crops`), 클립은 4~6프레임 균등(`npm run qa:clip`, 30초 초과 필수), 소리는 청취로만. (G7·G8)
3. **모든 판정표에 탈출구 2종 병기** — 「그 외: ___」 + 「전제 틀림, 재실측」. (G10)
4. **건별 응답 가능한 표.** 필수 필드 강제 금지 — 사유는 요청하되 부재 자체를 기록한다. (7편 U2)
5. **기록은 main 이, 회신 받은 그 턴에.** verbatim + 라벨 병존, 라벨이 원문을 대체하지 않는다. 번복은 원 행을 두고 `premise_fail` 새 행. **게이트 종료 = decisions.jsonl 커밋.**
6. **판정 대기 중 준비·수집은 계속, 비가역만 정지**(생성 발주·렌더 확정·자산 채택). (3편 22.75cr vs 2편 BGM 8곡)

## 게이트별

| # | 제시물 | 응답 | 목표 |
|---|---|---|---|
| **① 자료 범위** | 편 id 후보 1행 + **자산별** 권리표 — source-verify 원문 **무편집**, 기관 단위 뭉개기 금지 | 범위 지시 한 줄 + 행 override | 5분 |
| **② 원고 택1** | 초안 전문 + 비교표(척추·훅·리스크·도해 부담·커버 방향). main 추천·근거는 **제시물에** — 한 글자 답에도 전제가 남게 | 택1 | 1~2분 |
| **③ 3′ 판정** | shot-judge **원문 무편집** 건별 행 + 「어디까지 뒤졌나」 열(A 부적합에 「없다」 금지) + 탈출구 2종 | 건별 승인/기각/보류/재실측 | 판당 10분 |
| **④ 4-3R** | slides(무엇이 있나) + **원해상 크롭**(읽히나) + 이슈 번호표 — 두 해상도를 섞지 않는다 | 번호 지정 + 자유 발견 산문 | 15분 |
| **⑤ BGM** | 채택 1 + 대안 3 + 실측치(RMS) + 청취 4항목. **비동기** — 다른 층을 막지 않고, 미청취분은 ⑦ 청산표로 | 채택/교체 + 항목별 | 5분 |
| **⑥ 최종** | **2부 — 시청이 1부**, 에이전트 이슈 원문 표는 2부(shot-judge·fact-check 충돌 시 **두 원문 병기**, 충돌 자체가 판정 항목). 프레임 시트는 보조 | 표 건별 + 자유 발견 산문(이 채널이 게이트의 존재 이유 — G12) | 20분 |
| **⑦ 확정** | 실물 + 게이트 표 + **청산표**(보류 건마다 「현상 확정 시 이렇게 됨」) | **「확정」 = 명시된 일괄 승인** — 되묻기 금지, main 이 각 행 `explicit_absorb` 라벨 | 2분 |

재제시(round 2+)는 **변경 건만** + 전/후 비교 (③④⑥ 공통).

## 기록·지표

- 원장 `pilots/<id>/qa/decisions.jsonl` — 스키마는 `docs/specs/decisions.schema.md`. 도구: `gate:log`(present 선기록 → decide → to-defects) · `gate:metrics`.
- `reject`·`free_find`·`premise_fail` → `docs/defects.json`(guard:null = 승격 백로그) → 편 종료 후 가드 승격 → `eval:defects` 회귀. **사람이 잡은 결함을 안 옮기면 매 편 사람이 같은 걸 잡는다.**
- 지표 4: 대기·왕복·premise_fail 율·하류 유출. **목표 초과·왕복 2회 = 사람이 아니라 제시 형식의 결함 신호** — 재촉하지 않고 편 종료 후 개정 루프에 올린다.
