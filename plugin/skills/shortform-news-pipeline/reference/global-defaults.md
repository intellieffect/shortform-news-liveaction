# 전역 기본값 보기·바꾸기

"앞으로 모든 새 영상에 ○○", "기본 보이스를 ○○로 바꿔줘", "지금 기본값이 뭔지 보여줘"처럼 **한 편이 아니라 이후 새 편 전체**를 바꾸는 요청의 절차다. 한 편만 고치는 요청은 [production-state.md](production-state.md)의 편 수정 경로를 쓴다. 요청에 편 URL이나 "이 편"이 있으면 편 수정으로, "앞으로·모든 새 영상·기본"이면 이 절차로 본다. 어느 쪽인지 불분명하면 사용자에게 한 번 묻는다.

## 1. 지금 값 보여주기

```bash
npm run defaults            # 표로 출력 (--json 가능)
```

프롬프트 버전, 자막 프로필 버전·수치, 새 편에 실제 적용될 보이스(.env 우선 여부 포함), 후킹 장식·출처 스타일 버전, 로고, 공용 음원 수를 보여 준다. 출력 표를 그대로 사용자에게 보여 준다.

## 2. 요청을 장치에 대응시키기

| 요청 예 | 장치 | 변경 방법 | 흐름 |
|---|---|---|---|
| 새 영상의 제작 방향·표현 원칙·검수 방식 ("○○ 방식으로 만들도록 기본 프롬프트에 추가해줘") | 기본 프롬프트 `docs/PRODUCTION_PROMPT_V2_RESTORED.txt` | 본문 수정 → `npm run defaults -- prompt-bump --note "<사용자 요청 원문>"` | 설정값 |
| 기본 보이스·말 속도·높낮이 | `config/production-defaults.json` `narration.voice` | `npm run defaults -- voice --voice-id tc_… [--voice-name …] [--tempo 1.1] [--pitch 0] [--emotion normal]` | 설정값 |
| 말자막 크기·위치·서체 (앞으로 모두) | `config/production-profile.json` | `profile-archive` → 값 수정 → `profile-bump <새 버전>` | 설정값 |
| 공용 배경음악 추가 | `library/music/catalog.json` | [공용 음원 절차](../../shortform-news-input/reference/music-library.md) | 설정값 |
| 후킹 장식(밑줄 색·그림자·중앙 위치) | `config/hook-style.json` | 인텔리이펙트에 개발 요청 | 개발 |
| 출처·끝 크레딧 스타일 | `config/attribution-style.json` | 인텔리이펙트에 개발 요청 | 개발 |
| 로고, 자막 분절 규칙, 검사 계약(`hook-overlay@4`·`screen-text@2` 등) | presets·scripts·코드 | 인텔리이펙트에 개발 요청 | 개발 |

**수치·스타일은 프롬프트를 고쳐도 바뀌지 않는다.** 프롬프트는 방향만 담고 수치는 프로필·스타일 파일이 정한다. "자막 크게"를 프롬프트에 적지 않는다.

후킹 장식·출처 스타일·로고는 현재 파일을 모든 편이 컴파일 때 읽는다(편별 보관본 연결이 없다). 바꾸면 기존 편을 다시 컴파일할 때 소급되므로 이 절차에서 바꾸지 않고, 원하는 변경과 이유를 정리해 개발 요청으로 넘긴다고 사용자에게 알린다.

"모든 장면 4초 이하·문장당 2컷·카메라 모션·카운트업 자동 적용" 같은 자동 기본 기능은 장치가 없다. 기본값으로 만들 수 있다고 약속하지 않고, 편마다 요청하면 반영할 수 있다고 안내한다.

## 3. 바꾸기

- 사용자 요청 원문을 그대로 `--note`나 변경 기록에 옮긴다. 요약해 규칙으로 바꾸지 않는다.
- **기본 프롬프트**: 요청 문장을 가장 가까운 기존 문단에 추가한다. `[기사 URL]` 자리는 하나로 유지한다. 그다음 `prompt-bump`가 `v2-original@N+1`을 등록하고 보관본(`config/production-prompts/`)을 남긴다. 본문만 고치고 버전을 올리지 않으면 새 편 `start`가 거절한다 — 같은 라벨로 다른 본문이 기록되는 것을 막기 위해서다.
- **보이스**: voice_id는 Typecast 계정마다 다르다. 사용자가 이름만 말하면 Typecast에서 그 계정의 voice_id를 확인해 받는다. 명령이 ".env의 TYPECAST_VOICE_ID가 설정돼 있어 적용되지 않는다"고 경고하면 그 안내를 그대로 전하고, `.env`의 값을 바꿀지(또는 "API 키 등록.cmd"로 다시 등록할지) 사용자에게 묻는다. `.env`는 사용자 키 파일이므로 묻지 않고 고치지 않는다.
- **자막 프로필**: 값을 고치기 **전에** `profile-archive`를 실행한다. 보관본이 있어야 이전 버전으로 시작한 편이 계속 같은 자막으로 컴파일된다. 버전은 x.y.z로 올린다(크기·위치 변경은 minor).
- 음성·영상 생성, 렌더, 편 시작은 이 절차의 일부가 아니다. 새 기본값을 시험하려면 사용자가 새 편을 요청할 때 확인한다.

변경 뒤 `npm run defaults -- check`로 라벨·해시·보관본이 맞는지 확인하고 `npm run defaults`의 새 표를 보여 준다.

## 4. 소급하지 않음을 알리기

모든 변경 보고에 다음을 포함한다.

- 새로 **시작하는** 편부터 적용된다. 편은 시작할 때 프롬프트 사본·프로필 버전·기본값 사본을 `00_brief/`에 고정한다.
- 이미 음성을 만든 편은 그 편의 `02_production/voice.json`을 따른다. 기존 편을 새 기본값으로 바꾸려면 그 편을 지정해 따로 수정 요청해야 한다(음성은 다시 생성된다).
- 바뀐 파일 목록과 커밋. 명령이 바뀐 설정 파일만 명시해 자동 커밋한다(메시지 `기본값: …`, 편 확정 커밋과 같은 방식). 손으로 커밋하지 않는다. "커밋하지 않음"이 출력되면 그 이유(예: git 사용자 이름 없음, 다른 staged 변경)를 사용자에게 전하고 해결 뒤 같은 명령을 다시 실행한다.

## 설정값 흐름과 개발 흐름

| | 설정값 흐름 | 개발 흐름 |
|---|---|---|
| 대상 | 위 표의 "설정값" 장치 값 | scripts·src·plugin 코드와 지침, 스타일·로고·검사 계약 |
| 누가·어디서 | 고객 체크아웃의 `main`에서 `npm run defaults`·`npm run music` — 그 파일만 자동 커밋 | 인텔리이펙트가 워크트리·별도 브랜치에서 |
| 소급 | 없음(버전·보관본으로 고정) | 개발 쪽에서 판단 |

설정값 흐름에서 코드·지침 파일을 고치지 않는다. 요청이 개발 흐름에 해당하면 무엇을 바꾸려는지와 이유를 정리해 사용자에게 개발 요청으로 넘기라고 안내한다.
