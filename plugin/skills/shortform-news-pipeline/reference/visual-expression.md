# 이미지·도해·오버레이의 시각 표현

모든 영상에서 연출 설계 전에 [공통 표현 레퍼런스](visual-references.md)를 확인한다. 각 사례의 범용 판단과 개별 표현 선택을 구분하고 기사·자료에 맞게 재설계한다.

## 연출의 선택지

이미지·일러스트·인용·비교표·그래프·도해·모션그래픽을 내용과 흐름에 맞춰 자유롭게 활용한다. 내레이션을 직관적으로 보여주고 이해·몰입·시각적 재미를 높이도록 설계한다. 분위기·리듬·강조·장면 연결도 유효한 역할이다. 사용 빈도·등장 간격·장면별 배치는 고정하지 않는다. 추가하거나 생략할 때마다 필요성을 입증하거나 사유를 기록할 필요는 없다.

도해·인용·그래프는 표현 형식, 사진·일러스트·아이콘은 재료, 오버레이·전체 화면·분할·삽입 화면은 배치 방식이다. 이 선택지를 조합하며 한 종류를 고정 서식으로 반복할 의무는 없다. 배경 영상만으로 진행하는 구간도 같은 연출 선택이다.

| 떠올릴 표현 | 조합할 수 있는 재료와 움직임 |
|---|---|
| 대상 소개 | 인물·제품 컷아웃, 일러스트, 이름과 특징의 등장 |
| 인용·근거 | 발언자 사진, 원문 발췌, 핵심 구절 강조와 문서 확대 |
| 비교·추세 | 비교표·막대·선그래프, 대상 이미지, 같은 기준에서의 순차 공개 |
| 구조·원리 | 단면·분해도, 오브젝트 일러스트, 부분 확대와 연결 |
| 과정·인과 | 동일 대상의 상태 변화, 흐름·작용·결과를 이어주는 모션 |
| 공간·경로 | 지도·궤도·영역, 이동하는 대상과 경로 |
| 비유·분위기 | 사진 콜라주·상징적 일러스트·질감, 리듬과 장면 연결 |

이 표는 아이디어의 출발점이며 편마다 채울 목록이 아니다. 실제 자료의 특징과 이번 이야기에서 새로운 표현을 선택할 수 있다.

## 스타일과 합성의 완성도

프로젝트 브랜드와 이번 편의 미술 방향 안에서 타이포·색·선·형태·질감·모션이 어울리게 설계한다. 종이 스타일이나 특정 카드 모양을 기본으로 강제하지 않는다. 공통 자막은 기존 제작 프로필을 따르고, 인용·표·도해의 본문에는 내레이션 자막의 한 줄 규칙을 확대 적용하지 않는다.

- **위계·타이포:** 핵심 대상·문구와 보조 정보가 크기·굵기·대비·간격으로 구분되게 다듬는다. 인용은 문장과 발언자·출처가 함께 읽히고, 표는 같은 항목의 정렬과 여백으로 비교가 쉬워지게 한다.
- **색·선·형태:** 같은 의미를 가진 대상·연결선·강조는 알아볼 수 있는 시각적 연속성을 가진다. 그래프는 축·단위·척도를 보존하며 움직임이 값이나 차이를 왜곡하지 않게 한다. 도해는 대상의 특징과 관계가 형태 자체에서 읽히게 만든다.
- **이미지·일러스트:** 최종 표시 크기에 맞는 해상도, 깔끔한 가장자리, 의도에 맞는 시점·재질·조명을 확보한다. 사진·일러스트를 혼합하는 콜라주와 장면에 자연스럽게 녹이는 합성 모두 가능하다.
- **배경과의 합성:** 배경·국소 명암·오브젝트·관계선·텍스트·자막의 시선 순서와 가림을 함께 설계한다. 그림자·테두리·배경판·원근·마스킹은 이번 표현에 맞춰 선택한다. 이들은 필수 레이어나 고정된 쌓기 순서가 아니다. 풀블리드 배경 위의 컷아웃·삽입 자산까지 전체 화면으로 늘리지 않는다.
- **모션:** 등장 효과뿐 아니라 이동·연결·비교·변형·유지·퇴장이 설명과 리듬을 만든다. 모든 요소를 동시에 움직이거나 매번 같은 효과로 등장시킬 필요는 없다. 읽을 정보와 변화의 속도를 발화·음향·전체 흐름에 맞춘다.

가령 인용은 인물 컷아웃 뒤에 원문을 펼치고 핵심 구절을 강조할 수 있고, 실사 위 도해는 같은 대상에 연결선을 붙인 뒤 관계를 확장할 수 있다. 그래프는 기준을 유지하며 추세를 드러내고 관심 지점을 확대할 수 있다. 이는 구현 아이디어이며 고정 순서·시간·부품 처방이 아니다.

## Higgsfield 자산과 코드의 조합

코드로 표현하기 어려운 외형이나 이미지·일러스트·질감·공간감이 필요한 경우 연결된 Higgsfield를 활용한다. 코드 구현을 먼저 소진할 필요는 없다. 사용할 수 있는 도구·계정·모델·출력 기능은 [생성 제공자 지침](generation-provider.md)에 따라 실제로 확인한다.

생성할 재료와 코드로 제어할 정보를 장면에 맞춰 나눈다. 예를 들어 위성·입자의 외형은 생성하고 경로·영역·정확한 수치·문구·등장 시각은 코드로 합성할 수 있다. 따로 움직이거나 가려야 할 대상은 분리 자산으로 만들고, 한 덩어리로 쓰는 콜라주나 영상은 통합 자산으로 만들 수 있다.

생성 요청에는 필요한 시점·형태·미술 방향·배경·여백·분리 가능성을 반영한다. 투명 배경 지원은 추정하지 않고 결과를 확인하며, 필요하면 배경 제거·마스킹한 파생본을 만든다. 정확한 글자·수치·인용·축·관계는 검증 가능한 코드 합성으로 제어한다. 생성한 표현을 실제 관측 근거로 소개하지 않는다.

## 기존 제작 흐름에 연결

원고·자료와 함께 시각 표현을 구상하고 실제 합성에서 다듬는다. 별도 오버레이 승인 단계나 필수 계획표는 만들지 않는다.

- `concepts.json`의 기존 표현 선택·요소·상태·시선 우선순위에 이번 장면을 담는다. 중요한 선택만 기존 제작 노트에 남긴다.
- 생성 원본과 가공한 파생본은 편의 `02_production/`에 보존한다. 프롬프트·참조·실제 제공자/모델·비용은 기존 생성 기록을 사용하고, 채택 자산은 `visual-system.media.assets`로 연결한다.
- `motion.json`의 발화 앵커와 편별 장면 코드로 합성·모션·SFX를 구현하고 기존 compile/sync로 전달한다. 새 오버레이 정본이나 필수 JSON 필드는 추가하지 않는다.
- 기존 프루프와 [실물 검수](quality-review.md)에서 화면의 이해·몰입·완성도를 본다. 자산 단독 이미지와 실제 배경 위 합성 결과를 구분하고, 필요한 수정은 원고·자산·배치·모션 사이에서 선택한다.

이 문서는 연출 안내다. 표현 종류·사용량이나 스타일 항목의 충족 개수로 통과를 판정하지 않는다.
