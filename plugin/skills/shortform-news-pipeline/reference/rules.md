## §1 원고

- **R1-01 (U1) 자막 = `beats[].text` 그대로.** `overlays.overrides.json` 은 `card`/`headline`/`credit` 만, `caption` 덮어쓰기는 생성기가 거부. ✓
  - 사례: 대본은 클라이언트가 썼다 — 고쳐 쓰지 않고 **분할·치환만**. ✗
- **R1-02 인용 카드는 기사 원문 문장**(facts 원문 항목) — 대본 축약본이 아니다. 귀속은 이름+직함, 소속 표기는 facts 규칙. ✗ · 조판은 registry `quote_card@1`
- **R1-03 (U2) 자막 ≠ 화면 텍스트 — 두 층, 다른 규칙.** 자막은 내레이션의 쌍둥이(원고 그대로·모든 발화 비트·생성기는 줄바꿈과 강조만). 화면 텍스트는 **자막 문장을 복창하지 않는다.** 출처가 다른 두 갈래:
  - **① 온스크린 카드**(`onscreen@1`·headline·quote/cta card·counter 라벨) — 대본에 「자막(온스크린 텍스트)」 열이 있으면 **그 열이 문구의 단일 소스**(원문 보존). 없으면 훅 헤드라인·CTA·인용 카드에만 원고 문장을 쓰고 그 밖에는 넣지 않는다.
  - **② 보조 라벨**(`label_tag@1`·인셋 라벨·`credit_tag@1`) — 대본과 무관하게 **우리가 쓰는** 문구. 목적은 오인 방지와 출처 표기뿐이고 facts 상 의무인 경우가 많다. 근거를 `shots.notes` 에. ①의 「단일 소스」는 여기 적용되지 않는다.
  - 사례: **온스크린은 자막과 다른 조판으로 짠다** — 대본이 정하는 것은 *무엇을 담을지*, *어떻게 보일지*는 우리 몫. 남기는 글자는 **숫자·고유명사·인용**뿐이고 서술어는 내레이션 몫, 나머지는 그림 부품이 말한다. (2026-08-30 사용자 개정 — 폐기: `arrow_step@1`·`equation_block@1`·`bullet_list@1`)
- **R1-04 (U3) 한 사실 = 한 비트 = 한 표현.** 그래픽·온스크린·인셋 중 **가장 잘 표현되는 하나**를 그 사실을 말하는 비트에 **1회**. 계획은 `layer43_plan` 이 단일 소스. △
  - 사례: **카드 하나 = 비트 하나** — 두 비트에 걸치면 경계에서 사라졌다 다시 등장한다. 비트는 그 컷의 **payload(수치·주장)를 말하는 비트**. ✓ `[card-once]`
  - 사례: **병렬 나열 자막은 한 비트에 몰지 않고 발화 비트로 분산**(`icon_strip@1` 이 비트를 넘어 점등). ✗
- **R1-05 (U5) 4-3 계획에는 위치·크기·위계가 들어간다.** `layer43_plan.layout` 에 존·인셋 크기(S/M/L)·위계(H1~H4)를 정의하고 비트별 `layout` 에는 **존 이름만**. px 는 `npm run layout:43` 이 파생 — 손으로 x·y 를 찍지 않는다. ✓
- **R1-06 비트 안에서는 낱말 시각으로 쪼갠다.** 요소별 `*_in`(초, 비트 시작 기준)을 내레이션 낱말 시각에. 컷→비트 매핑은 `shots.onscreen_map` 에 근거와 함께 고정(생성기가 자동 판정하지 않는다). ✓ `[word-timed-in]` (`*_in` props 를 가진 부품인데 하나도 안 건 경우)
- **R1-07 온스크린이 자막과 동일한 텍스트를 말할 때만 그 비트 자막을 끈다**(`Beat.tsx norm()` 비교). 요약·다른 문구(CTA·슬랩 축약문)는 **자막 유지**. △
- **R1-08 같은 말 두 번 금지는 표기가 같을 때만.** 그래픽이 자막과 같은 수치를 같은 표기로 띄우면 `replaces_caption_line` 으로 그 줄을 비운다. 표기가 다르면(자막 "176만 기" ↔ 온스크린 "1,766,623기") **비우지 않는다** — 자막은 내레이션 쌍둥이가 우선. ✗
  - 예외: 도해가 같은 수치를 **다른 표기**로 띄울 때 사용자가 이중 노출 제거를 지시하면 허용 — 사유·날짜를 남긴다(4편 b06).
  - 층 의존: `replaces_caption_line` 은 **그래픽 부품**이면 graphics 층이 켜져 있을 때만 적용된다(온스크린 부품은 텍스트층이라 무관) → [layers.md §B](layers.md)

## §5 화면(shots)

- **R5-01 대상 자체(특정 실물·고유명사)를 말하는 비트에는 공개 게재본 제품 이미지가 보여야 한다.** 제품 없는 실사로 대체하면 문장의 주어가 화면에서 사라진다(A1). 사용권 미확정이면 `needs` + `clip_option`. ✗
- **R5-02 (U12 사례) 배경은 그 비트의 키워드를 수행한다(동사 포함).** 정적 더미·무신호·장식 배경은 부적합, **검정 배경 비트 0**. 키워드 실물의 공식 실사(커먼즈 CC BY 포함) > 생성. ✓ `[no-black-bg]`
  - 예외는 **사유를 `layer43_plan.layout.rules` 에** — 3편 b09 검정+카운터가 input 결정으로 기록돼 있다(소급 실측이 찾아낸 예외 조항).
  - **자료가 붙인 낱말을 그대로 들여오지 않는다** — 내레이션에 없는 낱말이 화면을 차지하면 뺀다(5편 b06 「하와이 실제 축척」). ✗
  - **자료에 구워진 라벨(영문 캡션 등)은 `crop` 으로만 뺀다.** 확대(`motion.scale`)로 밀어내는 것은 **영상 클립에서 안 먹는다**(G6 — `Background.tsx` 의 clip 경로는 `cropStyle` 만 쓴다). 9:16 을 지키며 확대하려면 `w = 0.5625·h·H/W`. ✓ `[video-scale-noop]`
- **R5-03 에셋 교체 단위 = 씬(문장), 변화 단위 = 비트**(크롭 이동·줌·자막) — **비트마다 다른 소스가 필요하지 않다.** ✗ (`check-shots` 5 는 반대 방향만 본다 — 인접 *씬*이 같은 에셋일 때 경고)
- **R5-09 정지 4초 초과는 B✗**(R5-03 의 짝). 5초 넘는 정지는 팬/줌으로 — 3′ 기준으로 **켄번스도 정지로 친다**. 예외: 그래픽 모션 부품이 있는 비트(registry `motion:true`), 대본이 배경을 지정한 비트. ✓ `check-shots` 8(B3)
- **R5-04 (U4) 배경이 키워드를 이미 보여주면 인셋을 쓰지 않는다.** 판정은 **실측으로**(U12) — 정지 프레임 한 장은 근거가 아니다. 제거한 인셋은 `inset_option{removed,why,date,restore}` 에 보관. ✗ · 역할·저해상·opacity 는 registry `inset@1`
- **R5-05 예측·시뮬레이션 이미지는 `label_overlay` 필수.** 전/후 비교에서는 예측 패널이 뜨는 시각에 라벨이 뜨도록 `label_overlay_in` — "현재" 패널 위에 "예측" 라벨이 먼저 뜨면 오독. △ `[label-provenance]` (`visual.label`·자산 label 만 본다. 옛 편 8건 미해결이라 경고)
- **R5-06 안전영역 좌우 80 / 상하 100, 헤드라인 ≥84px, 보조 ≥44px.** 보조 텍스트 하한은 **부품 구현에서 강제**한다. △ `mc:check`(MC) + `[safe-area-px]`(코드 도해 — registry props 가 `px` 라 밝힌 값만). **좌표를 데이터에 안 적고 부품 기본값에 두면 아무도 못 본다** — 실측 px 후보 2/5편(2026-09-02).
  - **단위는 registry props 설명의 「선두 토큰」으로 판정한다**(`"px"` · `"ratio? 0..1"` · `"sec?"`). G14: 아무 데나 있는 `px` 로 보다가 비율 prop 의 설명 문장(「px 를 부품에 직접 적지 않는다」)에 걸려 7편 신규 부품 3종에서 오류 4건이 났다 — **가드를 피하려고 설명을 깎는 일**이 생긴다. 더 단단하게 하려면 `props_units` 필드나 스키마 `$ref` 로.
- **R5-07 한 비트 최대 3겹**(배경 · 인셋 1 · 텍스트/그래픽 1). 라벨+다이어그램+인셋+자막 4겹은 과밀. ✓(`layout:43`)
- **R5-08 효과 부품은 컷당 1회** — 비트를 넘어 이어질 때 값이 역행하면 되감겼다 다시 열린다. ✗
- 부품 계약으로 옮긴 것 → registry `.rules[]`: 켄번스 3~10%·색 도표 줌 금지(`kenburns@1`) · 인셋의 역할·저해상·opacity(`inset@1`) · 텍스트만 비트 dim 0.6(`dim_gradient@1`) · 문서 증거 카드(`evidence_card@1`) · 수치 비례 점(`timeline_axis@1`)
- 존·크기·위계 값 → [templates/layer43_plan.json](../templates/layer43_plan.json) · 자막 밴드 → [overlays.schema.md](../../../../docs/specs/overlays.schema.md) · 시트에 생성물 0 → [track-3prime.md 헌장 개정](track-3prime.md) — 금지 대상은 *생성물*이지 **생성 대상 배지가 아니다**(시트 2차, [track-3prime.md 「시트는 두 번이다」](track-3prime.md))

## §5b 텍스트 걷어내기 — U4

> 사용자 2026-08-30: *"하나의 내용에 대해 다른 방식으로 중복되어 쌓여있거나 불필요한 텍스트까지 남아있어"*

- **R5b-01 (U4) 라벨 3분류** — ① 화면·자막이 이미 말하는 라벨 → **삭제** ② 사실 가드레일(예측·시뮬레이션·개념 도해·3D 모델) → **유지하되 최소**(지우면 오독). 확정 문구: `ESO 시뮬레이션 (예측)` / `ESO 예측 이미지` / `개념 도해 — 실측값 아님` / `NASA 3D 모델 (사진 아님)` ③ **AI 고지는 화면 라벨이 아니라 엔드카드 크레딧에만**(§8). ✗
  - 사례: 카운터·카드의 라벨이 자막과 같은 말이면 제거. 근거 크롭은 자막+온스크린과 3층이 되면 뺀다 — 출처는 엔드카드.
  - 사례: `label_tag@1` 은 출처·조건 라벨이지 **카드 대용이 아니다** → R5d-06
- **R5b-02 (U4) 같은 문구를 연속 비트에 반복하지 않는다** — 씬 진입 1회. ✓ `[label-not-card]`·10번 가드(앞 비트와 문구까지 같으면 오류, 같은 씬 2회는 경고)
  - 예외: **출처 성격이 바뀌면 두 번째 라벨이 정당하다**(실사 → 시뮬레이션). 판정을 `shots.notes` 에.
- **R5b-05 (U1·6편) 화면의 100% 가 비실사인 편** — 관측 사진이 원리적으로 없는 소재(100억 년 전 사건)는 §5b-01 ②의 「예외 표시」가 기본이 된다. 가드레일 라벨은 **종류별 첫 등장에 1회**(`상상도 — 실제 사진 아님` / `시뮬레이션`), 도해는 무라벨, 크레딧은 R5b-03 대로 비트마다. `asset_gaps.json` 의 `non_real_only` 가 대상 비트를 준다. ✗ (2026-09-02 6편 정정)
- **R5b-03 하단 크레딧은 이 규칙 밖이다** — `source: external` 이면 **의무**(CC BY 조건). 비트마다 나오는 게 정상. 라벨(무엇을 보고 있나)과 크레딧(누구 것인가)을 섞지 않는다. ✓

## §6 AI 생성 금지 (facts.md 7항, 파일럿마다 갱신)

- **R6-01 (U8) 실제 제품·고유한 형태가 있는 대상은 AI 생성으로 넘어가지 않는다.** 선택지는 둘 — ① 제품·고유 형태가 화면에 안 보이는 배경을 만들거나 ② 실제 공개된 공식 자료를 수집한다. 대상 자체는 코드 도해 또는 공식 자료로만. △
  - 범위(사용자 정정): '고유 형태'는 **특정 실물**을 말한다. 냉장고·태양광 패널 같은 **일반 사물은 생성 가능**(무브랜드·무로고). 스톡이 싸구려로 보이면 생성이 '더 적합'한 사유가 된다.
  - 사례(2편 #14): 특정 도시 **식별** 금지 / 익명 도시는 허용 / '유일한 별' 프레임에는 달·별 등 다른 밝은 천체 금지.
  - 금지 목록: 실제 관측 결과 흉내 · 실존 시설 외관 · 실존 인물 · 위성 실물 디자인 · 기업 로고 · 특정 도시 야경 · 같은 숫자의 두 의미를 한 프레임.
- **R6-02 생성·합성 도해를 실제 관측 화면 위에 얹지 않는다.** ✗ · 조건은 registry `veil@1`·`erase@1`
- **R6-03 생성 비트의 프롬프트 `avoid` 에 facts 금지항목을 그대로 적는다**(`gen.prompt_avoid`). 기각 변형은 `gen.alternatives` 에 사유와 함께. ✓ `[gen-banned-word]`(프롬프트가 facts 금지 대상을 부른다 — 오류) · △ `[gen-avoid]`(`prompt_avoid` 자체가 없다 — 경고)

## §U12 확인 방법이 규칙의 일부다

> 5편이 안전영역을 어긴 기전이 이것이다 — **규칙은 지켰다고 믿었는데 bbox 를 한 시점만 쟀다.** 규칙이 아니라 확인 절차가 빠져 있었다.

- **정지 프레임 한 장은 근거가 아니다** — 인셋 제거·움직임 판정은 전 구간 프레임 차분으로(R5-04).
- **축소 시트로 판정하지 않는다** — 인셋·도해 공존은 원해상 크롭 에지 검사(R5c-11). 축소 시트는 15px 급 겹침을 가린다.
- **애니메이션은 여러 시점의 union 으로 잰다** — 한 시점 bbox 는 움직이는 요소를 놓친다. MC 텍스트 폭은 폰트 메트릭이라 예측이 안 되므로 **1회 렌더 후 실측을 계약에 되기입**한다.
- **비트 단위로만 보면 반복을 못 본다** — 비트시트로 이어서(R5d-04).
- **0.4s 미만 창에 ebur128 통합(I)을 쓰면 −70 이 나온다** — 짧은 틈은 `volumedetect`(RMS). 엔드카드 **마지막 1초 무음** 체크. SFX 가청성은 스파이크가 불명이면 수치로 판정하지 말고 **사용자 청취 항목으로**.
- 렌더 없이 확인하는 사다리(studio → slides → 비트시트 3.4초 → 한 프레임 → 구간 렌더) → [commands.md 「렌더 없이 확인하기」](commands.md)

## §U13 원본 무수정 — 처리는 파생물에
