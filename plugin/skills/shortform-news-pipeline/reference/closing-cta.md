# 마지막 CTA — closing-cta@1

2026-10-06 고객 요청 4번(원문 보존): "‘위성공해’편 마지막 CTA가 다른 영상도 유지되게 필수 반영 부탁드립니다. “여러분은 어떻게 생각하시나요? 댓글로 의견 남겨주세요”" — 사용자 결정으로 나레이션 문장과 화면 알약 문구를 **둘 다** 모든 새 편에 넣는다.

## 계약

| 항목 | 값 |
|---|---|
| 기록 | `request.json` `closing_cta: "closing-cta@1"` (start가 새 편에 기록). 기록이 없는 편은 검사하지 않는다 |
| 나레이션 | 마지막 문장은 정확히 `여러분은 어떻게 생각하시나요? 댓글로 의견 남겨주세요.` (공백 정규화 후 일치) |
| 화면 | 노란 알약 `구독과 댓글 부탁드려요`. 공통 레이어(`ClosingCtaTrack`)가 그린다 — 장면 TSX에 넣지 않는다 |
| 시간 | 마지막 줄의 `댓글로` 어절 시작 ~ 마지막 줄 끝 + 12f, 본문 프레임 안으로 자른다. 끝 크레딧 페이지에는 겹치지 않는다. 시간은 자동 산출이라 편에서 정하지 않는다 |
| 모양 | 어두운 반투명 둥근 알약, 노란(#FFD16A) 글자 + 얇은 노란 외곽선, 중심 x540·y770, 글자 60px(≥44px). 스타일 값은 `scripts/lib/closing-cta.mjs`의 `CLOSING_CTA_STYLE`이 정본이고 버전에 묶인다 |
| 자막 | 말자막은 그대로 켜 둔다. 알약은 자막을 대체하지 않는다 |

## 제작자가 할 일

1. 마지막 문장 앞에 기사에 맞는 결론·여운 문장을 쓴다. CTA 문장은 대체·변형하지 않는다. 낭독 원문·`narration.json`의 마지막 줄이 위 문장이어야 한다.
2. 알약은 `compile`이 `timeline.closing_cta`로 만든다. 직접 고치지 않는다. 위치·크기를 바꾸고 싶으면 새 버전(`closing-cta@2`)을 만드는 개발 요청이다.

## 검사

`npm run editorial:check`·`produce run … render`의 컴파일이 `closing-cta@1` 편에서 다음을 오류로 막는다.

- `closing-cta-line`: 마지막 나레이션 문장이 CTA 문장이 아니다.
- `closing-cta-window`: 알약 구간이 비었다.
- `closing-cta-policy`: 알 수 없는 버전.

알약이 실제로 그려졌는지는 컴파일이 `timeline.closing_cta`를 만들고 공통 `EditorialFrame`이 그리는 것으로 보장된다(렌더 시 timeline 없이는 컴파일 오류).

## 경로별 적용

- **editorial-concept(기사 위임):** 위 계약이 기본이다. 기본 제작 지시(`v2-original@6`)에 같은 문장이 들어 있다.
- **script-faithful(제공 완성 대본):** 제공 대본 원문이 우선이며 고치지 않는다. 대본 끝에 이 CTA가 없으면 대본 뒤에 **별도 마지막 줄로 덧붙이는 것을 기본**으로 하고, 덧붙였다는 사실과 사유를 제작 노트에 남기고 사용자에게 알린다. 이 경로는 `start`를 쓰지 않아 기계 검사가 없다.
- **옛 편(기록 없음):** 소급하지 않는다. 기존 편에 넣으려면 그 편을 지정해 수정 요청한다.
