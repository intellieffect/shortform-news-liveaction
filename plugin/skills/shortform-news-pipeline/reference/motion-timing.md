# 발화와 모션 타이밍

## 하나의 사건으로 묶는다

나레이션의 단어, 도해 변화, 라벨, SFX를 같은 사건 ID에 묶는다. “열여덟 개”를 말할 때 셀 수가 완성되고, “한꺼번에”에서 배열이 결합되며, 결합 완료 SFX도 그 이벤트를 참조해야 한다.

각 요소는 네 시점을 가진다.

- `from`: 등장 또는 동작 시작
- `settled`: 완전히 보이거나 동작이 완료된 시점
- `to`: 읽기·관찰을 마치고 퇴장을 시작하는 시점
- `end`: 완전히 사라진 시점

시점은 `line + token_index + word + edge + offset_frames`로 적는다. 텍스트 검색만 쓰지 않는다. 같은 단어가 반복될 수 있고 원고가 바뀌면 조용히 다른 단어에 붙기 때문이다. `narration_word_sha256`가 다르면 컴파일을 막는다.

## 속도 곡선

아래는 표현 선택의 출발값이다. 동작의 의미에 맞춰 고르고 실제 결과로 확인한다.

- 등장: `ease-out` — 빠르게 의미를 보여주고 부드럽게 정착
- 위치·크기 변화: `ease-in-out` — 시작과 끝을 모두 읽게 함
- 퇴장: `ease-in` — 읽은 요소를 빠르게 정리
- 실제 등속 운동: `linear`

`cubic-in`·`cubic-out`·`quad-in`과 `[x1,y1,x2,y2]` cubic-bezier도 사용할 수 있다. 배열은 유한한 네 값이며 x1/x2는 0~1이다. 선택한 enter/move/exit 곡선은 실제 장면이 읽어야 한다. 공간의 궤적은 편별 코드에서 자유롭게 설계한다.

정량 표현에는 범위를 넘는 overshoot나 장식용 count-up을 쓰지 않는다. 움직임은 발화 전에 결과를 먼저 보여주지 않으며, 핵심 동사의 말끝에는 관찰할 수 있는 완성 상태가 남아야 한다.

## 지속과 퇴장

기준 대상은 여러 문장을 건너 유지할 수 있다. 새 문장이 시작됐다는 이유로 초기화하지 않는다. `state.keep/add/remove`는 개념 간 상태의 의미 계약이며 객체를 자동으로 그리거나 유지하지 않는다. 장면 컴포넌트가 실제 대상을 유지하고 사건 시각에 맞춰 변화를 구현해야 한다.

라벨 읽기 시간은 글자 수와 새 정보량으로 판단한다. 짧다는 이유만으로 일률적인 프레임 하한을 품질 통과 기준으로 삼지 않는다. 검사기의 12프레임 경고는 재생 확인을 요구하는 신호다.

`semantic_pairs`의 조건과 값은 `settled..to`가 겹쳐야 한다. `depends_on`은 수량 라벨이 배열 완성보다 먼저 뜨는 등의 순서 오류를 막는다.

## 확인

장면의 지역 시간은 `eventInConcept(timeline, conceptId, eventId)`로 가져온다. `eventProgress(frame, event, "move")`는 from→settled의 동작 상태를, `eventOpacity`는 등장·퇴장의 투명도를 계산한다. 시점이 같은 즉시 변화도 지원한다. 같은 사건의 SFX는 `motion.audio_cues[].bind`로 연결한다.

프로필을 쓰는 편은 컴파일 시 사건 직전·등장 중간·퇴장 중간 프루프도 생성한다. 프로필 변경은 timeline의 프로필 해시와 snapshot 대조에 반영되므로 다시 compile/sync한 뒤 검수한다.

`npm run editorial:compile` 뒤 각 이벤트의 from 직전, from~settled 중간, settled, to, end를 뽑는다. 정지표만 보지 말고 실제 속도로 경계 전후를 재생한다. 내레이션이 바뀌면 자막·장면·전환·SFX·ducking을 함께 다시 확인한다.
