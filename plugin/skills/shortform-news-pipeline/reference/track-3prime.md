### 트랙 헌장 — 새 파일럿에서 그대로 따른다

**목적.** 기존 파이프라인(0~6)은 "문장과 화면이 맞나"까지만 본다. 그 결과물은 정지 사진 + 켄번스로도 통과한다. 3′ 은 그 위에 **"영상으로 작동하나"**를 묻고, 부족한 곳을 실사 회수 → 생성 순으로 채우는 트랙이다. 기존 단계를 고치지 않고 덧붙인다.

**목표 (완료 조건, 숫자로).**
| 지표 | 기준선에서 측정 | 완료 조건 |
|---|---|---|
| A✗ (문장과 다른 것을 보여줌) | N | **0** |
| B✗ (켄번스만 / 정지 4초 초과) | N | **0** |
| moving (클립·영상 인셋 비트 수) | N/22 | 기준선보다 ↑, 목표치는 판정표에서 정함 |
| 크레딧 | — | 회수 단계 **0**, 생성은 사용자 결정 |
| 기준선 | — | **무변경** (워크트리 분리, 언제든 되돌림) |

**판정표에 「어디까지 뒤졌나」 열을 둔다** (2026-09-03 신설, G7·G10).
A 부적합을 「없다」로 적지 않는다 — **어디까지 찾아봤는지**를 적는다. 비트마다 이 세 칸이 채워져야 판정이 끝난다.

| 비트 | A / B | **자료를 어디까지 뒤졌나** | 조치 |
|---|---|---|---|
| b19 | A ✗ | 이 클립 t=18 만 봤다 · **같은 파일 나머지 42초 미확인** | ← 이 상태로 「도해 신설」을 제안하면 안 된다 |
| b19 | A ○ | 클립 60초를 10초 간격 6장으로 확인 · t=50~58 에 태양·L2·JWST | 시각 이동 |

7편 실측: b19·b20 을 **「궤도가 작다(크기 문제)」**로 적고 선택지를 「더 확대 / 다른 파일 / 도해 신설」로 냈다.
실제 문제는 **「그 시각에 대상이 없다」**였고 답은 **같은 파일의 뒤쪽**이었다 — **옳은 선택지가 표에 없었다.**
사용자는 내가 낸 셋 중에서 골랐고, 그 결정은 틀린 전제 위에 섰다.

**판정은 `shot-judge` 가 하고 main 은 고쳐 적지 않는다** — 이슈 원문 그대로 사용자에게 올린다([agents.md](agents.md)).

**기준.**
1. **판정 2축.** A 내용(주어·목적어 있음 / 배경지식 없이 알아봄 / 오인 없음) · B 표현(피사체가 움직임 / 동사를 화면이 수행 / 정지 4초 이내). **켄번스는 정지.**
2. **역할이 결정한다.** 문장이 사실을 주장하고 화면이 근거면 **증거 슬롯 → 실사 불변**(회수·재크롭·업스케일만). 비유·질문·정서면 **은유 슬롯 → 생성 가능**. 자산의 출처(관측 실사냐)로 판단하지 않는다.
3. **순서.** 회수(있는 영상·기관 영상, 크레딧 0) → 소진 판정(input, 문서로) → 생성. 앞 단계를 건너뛰고 생성하지 않는다.
   **단 `tone` 슬롯은 소진 판정을 면제한다**(2026-09-03, 8편). 이 순서는 **증거 슬롯을 지키는 장치**이지 배경 질감에 걸 이유가 없다 — 8편은 톤 배경을 스톡으로 버티다 b13 크롭 2회·파문 3회를 고쳤고, 그 비용이 생성(5~12 크레딧·2분)보다 훨씬 컸다. `metaphor` 슬롯도 「A✗ 를 닫는가」가 아니라 **「더 적합한가」**로 판단한다.

### 모델·설정 (2026-09-03 실측, Higgsfield)

| | 5초 단가 |
|---|---|
| `seedance_2_5` (도구 기본값) | 32.5 |
| `kling3_0` 기본(sound on) | 10 |
| **`kling3_0` · `sound: off`** | **7.5** |
| `kling3_0` · `mode: pro` · `sound: off` | 8.75 |

- **오디오는 끈다.** 내레이션·BGM 이 이미 있다. `sound: off` 만으로 25% 가 빠진다.
- **모델을 비교한 뒤 발주한다.** 도구 기본값이 4배 비쌌다 — 8편 첫 견적 260 → 실제 96.
- `generate_video_batch` 로 병렬. 프리셋 추천으로 반려되면 `declined_preset_id` 로 거절하고 다시 낸다.
- 길이 단가는 **선형**이다. 길게 뽑아 나눠 써도 안 싸진다 — 다만 **같은 씬 두 비트는 한 클립**으로(컷 없이 이어진다).
4. **생성 규약.** 글자·선 없음 · facts 금지항목은 프롬프트 `avoid` · i2v > t2v · 저가 탐색 → 채택분만 고급 · 실사 대안은 `clip_option` · 원본은 input `gen/<pilot_tag>/`, 로그는 `gen_plan.md`. **AI 고지는 화면 라벨이 아니라 엔드카드 크레딧에만**(`AI 시각화 (Higgsfield · Kling 3.0)`, i2v 시작 프레임 출처는 `시작 이미지:` 접두) — 1편의 "`label_overlay` 'AI 시각화 · 개념도' 필수"는 2026-08-30 사용자 결정으로 폐기. 화면 라벨은 오인 방지가 필요할 때만("○○ — 실물 아님").
5. **검색어는 문장의 명사에서.** 기존 화면의 프레이밍에서 뽑지 않는다.

**하지 않는 것.** 0~6의 순서·방법 변경 · 기준선 root 파일 수정 · 소진 판정 없는 생성 · 확인 1 승인 전 승격 · BY-SA 자산 · 관측 사진 i2v(없던 움직임 조작).

**산출물.** `docs/specs/shot_fit.md`(판정표·회수 기록) · `asset_brief.json` v2(input 요청) · `docs/specs/gen_plan.md`(모델 매트릭스·프롬프트·job_id·판정·크레딧) · `shots.json` 추가 필드(`clip_option`·`gen{}`·`label_overlay`) · 후보 v2 렌더 + 검토 시트.

**게이트.** 확인 1에 "실사판 vs 생성판" + 생성 목록·라벨 문구·프롬프트 제출 → 클라이언트가 AI 금지 장면 지정(정의서 §7.3) → 승인 시 `pilot/<name>` 머지 + shots.json root 되밀기 + 6 재실행.


**헌장 개정(2026-08-31, 4편 실증으로 위치 승격).** 원래 판정·생성은 "6 최종 후보 뒤 워크트리 분리"였다. 3편(사용자 "지금 진행")·4편(3단계 직후, U1)에서 앞당겨 실행한 결과가 더 좋았다 — 확인 1 시트가 최종 화면이 되어 4-0~4-6 렌더가 한 방향으로 흐르고, 되돌림은 `clip_option`(배경)·`inset_option`(인셋)·`gen_rejected`(기각 생성)·`graphics_disabled`(도해) 4계층으로 충분했다. 따라서:
- **신편 = 3′ 기본**(같은 브랜치). 헌장 지표(A✗ 0·B✗ 0·moving↑)는 확인 1 전 충족으로 앞당긴다. 단 시트는 정지라 B축 완전 판정이 안 되므로 **판정은 2회** — 3′(시트 기준) + 최종 이슈 스윕(1초 전수·움직임·겹침 실측).
- **납품된 편 재작업 = 옛 트랙**(6 뒤·워크트리 분리·기준선 무변경) — 아래 원문 헌장이 그대로 적용된다.
- 크레딧 게이트(생성 착수 전 사용자 결정)·회수 먼저·소진 판정 순서는 위치와 무관하게 유지.
- 확인 제출물(2026-08-31 재개정, 사용자): 신편 기본 = **v1 수집판 + v2 생성판 2종** + 되돌림 목록 — 시트는 수집 기준으로 먼저 승인받고, 생성은 v2 에서 병렬판으로. 3종 비교(2편)는 클라이언트 확인 편에만.

### 3′ 앞당김의 시작 (3편)

헌장은 "6 최종 후보 뒤 워크트리 분리"지만, 사용자가 "지금 잠그자"면 같은 브랜치에서 진행한다. 되돌림 = `visual.clip_option`(배경)·`inset_option`(인셋)·`gen_rejected`(기각 생성). 렌더는 vN으로 이력(3편 v1~v10), 데이터가 바뀌면 진행 중 렌더를 `TaskStop`하고 다시 돌린다.

### 시트는 두 번이다 (2026-09-01 명시 — 「시트 1차」라는 낱말에만 암시돼 있었다)

| | 언제 | 무엇을 판정하나 | 생성 |
|---|---|---|---|
| **시트 1차** | 3 | 수집·공식 소스·게재본·도해만으로 **화면이 서나** — [시트 검토 3질문](#시트-검토-3질문-3단계-사용자-검토-3회를-1회로) | **결과물 0** |
| **시트 2차** | **3′ 뒤** | **어느 비트가 생성으로 가고 왜인지** — 판정 결과가 화면에 보인다 | **대상 배지만**, 결과물은 여전히 0 |
| 생성판 | 8 (v2) | 실제 생성물 | 병렬판 |

**확인 1 에 올라가는 것은 2차다.** 「시트에 생성물을 올리지 않는다」(1차 시트는 **수집 기준**으로 승인받는다 — 위 헌장 개정 2026-08-31)가 금지한 것은 *아직 만들지도 않은 AI 영상을 시트에 넣는 것*이지, **어느 비트가 생성 대상인지 표시하는 것이 아니다** — 후자는 오히려 확인 1 의 제출 요건이다(생성 목록·라벨·프롬프트 → 클라이언트가 AI 금지 장면 지정, 게이트 11).

- 2차 시트·슬라이드는 비트마다 **생성 배지**를 단다: `gen.status: planned` → `AI 생성 예정` · `adopted` → `AI 생성` · `rejected`·`superseded` → 표시 없음. 슬라이드에는 `gen.prompt` 요지와 `prompt_avoid` 도 한 줄.
- 배지가 없으면 게이트 11(클라이언트의 AI 금지 장면 지정)은 **볼 물건이 없어 돌지 않는다.**
- 명령은 같다(`npm run still:sheet` · `npm run slides`) — 1차와 2차를 가르는 것은 **시점**이지 도구가 아니다.

(원문 헌장 — 재작업 트랙용) 3′ 은 기준선(6의 최종 후보)이 납품 가능한 상태에서 **워크트리를 분리해** 시작하는 별도 트랙이다. 실패해도 돌아갈 곳이 있고, 확인 1에 "실사판 vs 생성판"을 나란히 올릴 수 있다.

```
       승격    확인 1(생성 목록) 승인 → pilot/<name> 머지 → shots.json root 되밀기 → 6 재실행(h264)
```

### 3′ 판정 기준 (2축) — 원본 `docs/specs/shot_fit.md`
- **A 내용**: A1 주어·목적어 화면 안 / A2 배경지식 없이 알아봄 / A3 오인 없음
- **B 표현**: B1 피사체가 움직임(**켄번스는 정지**) / B2 문장의 동사를 화면이 수행 / B3 정지 4초 초과 금지
- 조치: A✗ 또는 A△+B✗ = 재제작 · 한 축 미달 = 보강 · 그 외 유지
- **유지/생성은 자산 출처가 아니라 비트 역할로** — 문장이 사실을 주장하면 증거 슬롯(관측·기관 실사 불변), 비유·질문·정서면 은유 슬롯(생성 가능)
- 순서 원칙: **회수 → 소진 판정 → 생성.** 위성공해에서 B✗ 10 중 9를 실사 회수로 해결, 생성은 5비트

### 3′ 생성 규약 — 원본 `docs/specs/gen_plan.md`
- 생성물에 글자·선 없음(텍스트는 overlays). 생성 비트는 `label_overlay` "AI 시각화 · 개념도" 필수. facts 금지 항목은 프롬프트 `avoid`로
- i2v > t2v (실사가 좋으면 움직임만). 클립 = 비트 + 0.5s, 9:16, 무음, 변형 2~3 → 9:16 시트 비교
- 모델은 카탈로그(30종) preflight 후 선택. 저가로 방향, 채택분만 고급 1회. 크레딧·계정은 사용자 결정
- 실사 대안은 `visual.clip_option`에, 생성 원본은 input `02_production/gen/v2/`, 로그는 `gen_plan.md §실행 로그`
- 업스케일(bytedance/topaz)은 생성이 아니다 — 실사 내용 무변경, 변경 표시만

#### 판정 절차 (R1·R2·R11 종합)
1. 비트의 **역할**을 먼저 정한다 — 문장이 사실을 주장하고 화면이 그 근거면 **증거 슬롯**, 비유·질문·정서면 **은유 슬롯**
2. 증거 슬롯은 실사 유지(R8). 회수·업스케일·재크롭만
3. 은유 슬롯 + (A✗ 또는 B✗ 또는 "더 적합"할 때) → 생성 후보(R7)
4. 실사 불가능은 input **소진 판정** 문서가 있어야 생성 근거가 선다 (b09)
5. 생성물: 글자·선 없음, `label_overlay` "AI 시각화 · 개념도", facts 금지항목은 프롬프트 `avoid`, 실사 대안은 `clip_option`

### 3′ 생성 v2 — 출처 기준 (2026-08-30, «위성공해» 2편, 사용자 "pexels 같은 사이트에서 우리가 직접 수집한 영상을 ai 생성으로 더 적합한 영상을 만드는 과정")
역할(증거/은유) 판정 위에 **출처 축**을 더한다. 둘 다 통과해야 생성 대상.
- **제외** = 클라이언트 제공 자료(`cut_map.script_asset`) + 실물·관측 기록(제품 실사·관측소·기관 3D 데이터). 업스케일만 허용.
- **대상** = 우리가 수집한 스톡(Pexels·Commons 등 은유·분위기 자리). "더 적합"이 조건 — 이미 A○B○·네이티브 세로면 강제 아님.
- 생성 **사유에 규격 결손을 포함**한다(업스케일 배율 ×1.5·×1.78 같은 실측). v1 기준(적합도만)은 이걸 놓쳐 b21–b24를 뺐다.
- 생성·합성 도해를 **실제 관측 화면 위에 얹지 않는다**(erase@1 구현·미적용 사유, veil@1 규칙과 같은 취지).
- 실사는 `visual.clip_option`에 보관, 생성물은 `credit: null` + 엔드카드 AI 고지 줄. 원본은 input `02_production/gen/<pilot_tag>/`.
- **헌장 B✗ 예외**: 대본 「화면 구성 제안」이 배경 자체를 지정한 비트(사진1 오프닝·수미상관 복귀)는 정지여도 유지 — 사용자 결정, `layer43_plan.layout.rules`에 사유. 헌장과 대본이 부딪히면 항상 사용자 결정 항목으로 올린다(C7 사례: A 헌장 우선 / B 대본 우선 → B).
