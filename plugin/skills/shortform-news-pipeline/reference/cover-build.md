# 커버 생성·수정·검수

판단 기준은 [cover.md](cover.md). **문구·장면·배치를 함께 이미지 생성 도구에 전달해 완성 커버를 만든다.** HTML/CSS 템플릿 조립을 기본 경로로 사용하지 않는다.

## 생성 지시문

먼저 영상의 사실과 표현 의도를 짧게 정리하고 [고정 스타일](cover-style.md)의 기준 PNG를 연다. [표현력과 실물의 신뢰성](cover.md#표현력과-실물의-신뢰성을-함께-설계한다)에 따라 `brief.md`에 **궁금증 / 이를 전달할 구도·비유 / 실물에서 유지할 특징과 오해 위험**을 짧게 적는다. [예시](cover-examples.md)는 장면 판단에 참고하며, 제목 스타일과 부수 텍스트를 편마다 새로 설계하지 않는다.

지시문에는 다음을 연결해서 쓴다.

- 영상이 전달하는 사실과 시청자가 궁금해할 지점.
- **그 사실을 보여줄 장면:** 대상, 행동·관계, 필요한 비교. 단순히 '눈에 띄는 썸네일'이라고 주문하지 않는다.
- 이미지 안에 들어갈 **제목 두 줄의 정확한 한국어 문구와 줄바꿈**. “제목과 로고 또는 미수령 표시 외 텍스트 없음”을 명시한다.
- [고정 스타일](cover-style.md)의 하단 중앙 로고 영역. 로고가 없으면 회색 점선 박스와 정확한 ‘로고 영역’ 문구를 넣고 장면과 겹치지 않게 한다.
- 고정 기준 PNG를 스타일 입력으로 제공하고 제목의 위치·크기·서체 인상·왼쪽 정렬·흰색/연두색을 유지하도록 지정한다. 중앙 장면은 이번 영상에 맞게 설명한다.
- 각 입력 이미지의 역할과 보존 범위, 이번 소재에서 실제로 피해야 할 오해. 소재 사진에서 참고할 형태·물성과 새로 설계할 구도를 구별해 지정한다.

예를 들어 '커피에 크림 부을 때 / 그 무늬, 태양에도'라면 커피 속 크림과 태양 표면을 나란히 보여준다. 두 이미지가 실제로 같은 물질이라는 인상을 주지 않고, 관측 자료를 재구성했다면 제작 기록에 그 성격을 남긴다. 기준 PNG의 두 줄 제목 스타일과 고정 로고 영역을 유지한다.

## 도구 호출과 수정

1. 참조할 로컬 이미지를 먼저 열어 본다. 새 시안인지, 기존 시안 편집인지 구분하고 대상 입력만 제공한다. **수정은 해당 기존 시안을 편집 대상으로 제공한다.** 먼저 `brief.md`에 유지할 장점과 바꿀 부분을 적고, 프롬프트에도 보존할 구도·비유·사물·문구 및 변경할 형태·물성·강도를 구체적으로 구분한다. 단순히 ‘더 현실적으로’라고만 지시하지 않는다.
2. 현재 환경에서 사용할 수 있는 이미지 생성·편집 도구를 호출한다. 이 작업에서 검증한 도구는 `image_gen`이다. 다른 환경에서는 실제 제공되는 도구의 입력·저장 방식을 확인한다. 도구가 없으면 가능한 대안과 막힌 범위를 알린다.
3. 생성 원본을 보존하고 편별 작업 폴더에 복사한다. 요청한 규격과 **실제 반환 파일의 크기**를 구분해서 기록한다.
4. 결과를 열어 검수한다. 수정본은 이전 시안과 같은 표시 크기로 나란히 확인해, 지적한 오해가 줄었고 보존하기로 한 전달력·표현력이 남았는지 기록한다. 하나만 충족하면 해당 부분과 유지할 부분을 다시 지정해 수정한다. 프롬프트를 저장했다고 같은 픽셀을 재생성할 수 있다고 보지 않는다.
5. 요청한 시안이 준비되면 이미지와 비교 화면을 보여준다. 명확한 문제가 해소되면 멈춘다. 새로운 근거 없이 계속 다시 생성하지 않는다.

참조 이미지가 없는 새 생성에는 불필요한 이전 이미지를 넣지 않는다. 한국어 오탈자·라벨 오류를 발견하면 최종본으로 제시하기 전에 수정한다. 글자만 수정했어도 그림이 바뀔 수 있으므로 주변 내용까지 본다.

## 검수

| 확인 | 결과에서 볼 것 |
|---|---|
| 내용 | 문구와 장면이 영상의 사실·시제·불확실성과 맞는가. 생성한 개념을 실제 증거처럼 보이게 하지는 않는가 |
| 장면 | 대상을 알아볼 수 있고, 비교·변화·관계가 문구에 설명을 더하는가 |
| 실물의 신뢰성 | 강조된 형태·물성·규모·연결이 다른 현상이나 실제 인과로 읽히지 않는가. 관측 참조와 표현용 확대의 역할이 구별되는가 |
| 수정 전후 | 지적된 비현실성은 줄고, 유지하기로 한 비유·시선 흐름·대상 강조가 남았는가. 과장을 낮추며 정보와 관심까지 지우지 않았는가 |
| 디자인 | 기준 PNG와 같은 표시 크기에서 제목의 위치·크기·서체 인상·왼쪽 정렬·흰색/연두색이 유지되는가. 핵심 장면이 주제를 설명하고 하단 중앙 로고 영역과 겹치지 않는가 |
| 글자 | 제목의 문구·두 줄바꿈·숫자·고유명사와 로고 미수령 시 ‘로고 영역’ 표시가 정확한가. 허용한 제목·로고 표시 외 텍스트가 없는가 |
| 축소·노출 | 휴대폰에서 작게 보아도 제목과 장면을 알아보는가. 대상 플랫폼에서 예상되는 크롭·UI에 핵심 내용이 가리지 않는가 |
| 파일·기록 | 열리는 이미지인가. 실제 크기·사용 입력·생성 지시문·수정 계보·출처가 기록됐는가 |

전체 이미지와 축소 화면을 실제로 확인한다. 배포 화면을 확인하지 않았다면 확인했다고 기록하지 않는다. 과거 플랫폼 실측값을 현재 모든 화면에 고정 적용하지 않는다. 정확한 납품 규격이 있으면 별도 출력본을 만들고, 변환 뒤 글자·크롭을 재검수한다.

이 검수는 제작자가 결과를 보고 수행한다. 기존 영상의 `shots:check`·`credits --check`나 구형 `safezone.sh` 실행을 생성 커버의 검수 완료로 간주하지 않는다.

## 저장과 기록

```text
design/thumbnails/<편>/v<N>/
  brief.md              영상의 사실·훅·시안별 장면 의도
  prompts/A.txt         실제 사용한 생성 지시문; 수정 시 별도 파일
  references/           필요한 입력 자료의 보관본
  A.png                 생성 원본
  A-r2.png              수정본; 앞 버전 보존
  manifest.json         시안별 생성·출처·검수 기록
out/pilots/<편>/thumbnails/v<N>/
  A.png                 사용자에게 보여줄 출력본·필요시 비교 이미지
```

기록 안의 경로는 저장소 루트 상대경로로 통일한다. 임시 도구 경로를 최종 보관 경로로 삼지 않는다. 프롬프트와 함께 **실제 생성 PNG도 보존**한다.

`manifest.json`은 [cover-record.json](../templates/cover-record.json)을 복사해 채운다. 입력 자료가 없으면 `reference_inputs`는 빈 배열이다. 입력이 있으면 파일 경로, 역할(`style`·`subject`·`evidence`), 처리(`preserve`·`reinterpret`), 출처와 사용 조건을 적는다. 원본 보존이 필요한 `evidence`는 `preserve`로 기록한다. 모델명·작업 ID가 반환되지 않으면 추정하지 않고 `null`로 둔다. 필드 설명은 [schemas.md](schemas.md).

`review.status`는 `draft`(미검수)·`needs_revision`(수정 필요)·`reviewed`(제작자 검수)·`approved`(사용자 채택)로 구분한다. `checked`에는 실제 확인한 내용, `issues`에는 남은 결함을 쓴다. 사용자 채택은 발행 허가를 뜻하지 않는다.

`pilot.json`이 있는 편은 `thumbnails`에 `method: "image_generation"`, `target`, `manifest`, `candidates[]{id,file,status}`를 기록해 산출물을 찾게 한다. 기존 기록이 있으면 `history`에 보존하고 새 작업을 가리킨다. 과거 HTML 시안 대장을 새 형식으로 소급 변환하지 않는다.

사용자가 썸네일을 확정하면 해당 시안의 `review.status`와 `pilot.json.thumbnails.candidates[].status`를 `approved`로 맞추고 사용자 지시 원문을 확인 근거로 보존한다. `npm run videos`를 실행해 영상 목록도 갱신한다. 작업 워크트리와 사용자가 여는 주 작업트리가 다르면 파일·확정 기록을 주 작업트리에 반영한 뒤 그곳에서도 실행한다. 생성된 `out/videos.html`의 해당 편 대표 이미지와 썸네일 다운로드 경로가 확정 출력본을 가리키는지 확인한다. `file://`로 이미 연 화면은 새로고침해야 하고, 로컬 서버는 새로고침 시 기록을 다시 읽는다. 목록은 `approved` 파일을 우선하므로 기존 `deliver/`를 덮어쓸 필요는 없다.

요청한 시안 전체와 수정 이력을 보존한다. 납품 묶음에 넣는 작업까지 요청받으면 새 `deliver/v<N>/`에 포함한다. 기존 납품본은 덮어쓰지 않는다. 커버 입력 자료의 출처는 자체 기록으로 관리한다. 영상 크레딧 명령에 자동 포함된다고 가정하지 않는다.

## 사용자에게 보여주기

수량 미지정 제작은 후보 세 장을 각각 대화의 이미지 표시 기능으로 띄우고 파일 링크도 제공한다. 비교 화면을 만들 때도 후보만 넣고 기준 PNG·내부 검수 화면은 제외한다. 그 기능이 없는 환경에서는 실제 PNG를 이미지 뷰어로 연다. 사용자 지정 수량이나 특정 후보 수정 요청은 그 범위를 따른다. 파일명이나 저장 경로만 전달하고 끝내지 않는다.

HTML은 필요할 때 결과 비교용으로만 쓴다. 브라우저를 사용하면 현재 환경의 브라우저 지침을 따른다. `design/thumbnails/_templates/`와 `render.sh`·`sheet.sh`·`safezone.sh`는 과거 HTML 시안 재현용이며 새 생성 커버의 제작·검수 경로가 아니다.
