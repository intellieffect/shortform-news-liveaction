# 제공 자료 수령 현황 — «<pilot>»

갱신: <YYYY-MM-DD HH:MM> — <수령 경로·messageId>. **원문은 수정 없이 보존**하고 파생물은 `02_production/` 에 만든다.
상태는 ✅ 수령 / 🟡 부분 / ❌ 없음 셋으로만 적는다. **「아마 있을 것」은 ❌ 다.**

## 이 편은 어느 쪽인가 — 먼저 고른다

| | **대본 수령 편** | **자작 편** |
|---|---|---|
| 예 | 1·2편(한겨레 완성 대본) | 3·4·5·6·7편 |
| 원고 | 클라이언트 대본이 **단일 소스** — 우리가 다시 쓰지 않는다 | 기사에서 우리가 쓴다(`narration_drafts/` 안 3~4갈래 → 사용자 택1) |
| 화면 | 대본의 「화면 구성 제안」·지정 참고자료를 먼저 따른다 | `facts.md` → 비트 → 소싱 |
| 아래 표 | 2·4·5번이 산다 | 2·4·5번은 **해당 없음** — 그 줄에 「자작」이라고 적는다 |

한쪽을 지우지 말고 **어느 쪽인지 한 줄로 적는다** — 나중에 「왜 대본이 없나」를 다시 묻지 않게.

> 이 편: **<자작 / 대본 수령>** — <근거 한 줄>

## 수령 현황

| # | 항목 | 폴더 | 상태 | 비고 |
|---|---|---|---|---|
| 1 | 주제·기사 원문 (제목·작성자·게재일·URL) | `01_원문_기사/` | ⬜ | `npm run new -- <id> --url <URL> --fetch` 면 원문·메타·게재 이미지까지 받는다 |
| 2 | 완성 대본 최종본 | `02_완성_대본/` | ⬜ | 자작 편이면 「자작」 |
| 3 | 최종 내레이션 WAV | `03_나레이션/` | ⬜ | 없으면 TTS 대체 가능 여부를 **먼저 확인**한다(목소리는 되돌리기 비싸다) |
| 4 | 내용·화면 표현 기준 | `04_표현기준/` | ⬜ | 자작 편이면 `02_production/facts.md` 가 이 역할 |
| 5 | 사진·영상·그래픽 | `05_참고자료/` | ⬜ | 매핑은 `05_참고자료/INDEX.md`. **9:16 크롭 시 업스케일 ×2.5 초과면 못 쓴다** |
| 6 | 사용권 확인 | `05_참고자료/RIGHTS.md` | ⬜ | **라이선스는 페이지가 아니라 자산마다.** 게재 사진은 기본 ❌ 참고용 — 1차 출처로 간다 |
| 공통 | 브랜드 자산 (로고·서체·컬러·인트로/아웃트로) | — | ⬜ | 없으면 임시 브랜딩(Pretendard + 채널 문법 색) |
| 공통 | 생성 계정·크레딧 | — | ⬜ | 크레딧 소모는 `02_production/credit_log.md` 에 기록. **생성은 회수를 소진한 뒤** |

## 파일 목록

```
01_input/
├── 00_mail_raw/<수령 원문>            # 메일·메신저 원문 (gog gmail get 등)
├── 01_원문_기사/<기사 원본>            # 수정 금지. MD5SUMS 로 잠근다
├── 02_완성_대본/<대본 원본>            # 대본 수령 편만
└── 05_참고자료/<제공 자료>             # 원본 그대로. 파생은 02_production/
```

## 수령 절차

1. ⬜ 수령 경로 기록(누구→누구, 언제, messageId)
2. ⬜ 원본 그대로 저장 + `MD5SUMS`
3. ⬜ 읽는 판 추출(파생물임을 파일명·표로 남긴다)
4. ⬜ `02_production/facts.md` — 수치·고유명사·인용 + 불일치 항목
5. ⬜ **권리 실측** — `RIGHTS.md` 자산마다 (`@agent-shortform-news:source-verify`)
6. ⬜ 미확인 항목을 **클라이언트 확인 목록**으로 한 번에 묶어 올린다 (건별로 묻지 않는다)
