# 사실 잠금 — facts.md 작성법

정본 예: `news/hani_satellite_pollution/02_production/facts.md` (30항목) · 6편 `news/hani_disc_flip/02_production/facts.md`(사실 24 + 1차출처 P 7 + 불일치 D 6 — 기사 밖 1차 출처 문장을 P 로 따로 둔 예). 뼈대: `templates/facts.md`.

## 구조 (순서 고정)

1. **머리** — 기사 제목·부제·URL·작성자·게재일(없으면 "미확인"), 1차 출처(연구·기관).
2. **문단 번호표** — 기사 본문을 ¶1…¶N으로, 각 ¶의 시작 문구. 소제목은 `—` 행. 이후 모든 근거는 ¶로만 적는다.
3. **화제** — `## 화제` 한 줄 + `### 핵심 키워드` 표. **둘의 지위가 다르다.**
   - **「이 기사가 주장하는 것」 한 문장** — 데이터가 아니라 **문맥**이다. 매칭·소싱·검사 어디에도 안 들어간다.
     하는 일: ① 표를 뽑을 때 방향 ② 표의 구멍 찾기 ③ 에이전트에게 주는 편의 주장.
     **한 문장으로 쓴다** — 길어지면 요약이 되고, 요약은 화제가 아니다.
   - **핵심 키워드 표**(`낱말 / ¶ / 실물 / 표기 변이`) — 이게 **데이터**다. 매칭·소싱 발주·등급 판정·집계가 전부 이걸 쓴다.
   - **실물 = 세상에 그 사진·영상이 있나.** 확보 여부가 아니다. 권리로 막혔으면 `❌ 권리(LBNL ARR)` 처럼 사유까지 — P0 `source-verify` 판정을 그대로 옮긴다.
   - **정의상 볼 수 없는 것**(암흑물질·윔프 같은)은 `❌ 정의상 불가`. 8편이 이 한 줄이 없어 윔프 배경 **생성을 3회** 시도했다.
   - **표기 변이가 비면 매칭이 0 이 된다** — 내레이션은 "지하 1480미터", 표는 "1480m". 아래 §6 표기표와 같은 정보다.
   - **낱말 개수에 상한을 두지 않는다.** 기사에 따라 다르다 — 7편(제원 비교 기사)은 9개가 자연스러웠다.
   - 이 표가 아래로 흐른다: `beats.json kw[]` → `asset_gaps` 검색어 → `shots.json kw_served[]` → `shots:check` 의 `kw N/M`.
4. **화면에 반드시 정확해야 하는 것** — 표: `# / 사실 / 기사 근거 ¶ / 대본 컷·표현 / 대조(✅·⚠️·—) / 화면 표현 규칙`. 대본이 쓰는 사실은 전부, 안 쓰는 핵심 사실도 번호를 준다(보조 인용 후보).
5. **캡션에만 있는 사실** — 이미지 캡션이 근거인 것(촬영일·의미 범례·예측 여부).
6. **고유명사 표기·발음** — 자막 표기(대본 우선) / 기사 표기 / TTS 발음 / 비고. 숫자 읽기 포함.
7. **대본 내부 불일치** — 우리가 고치지 않는다. 클라이언트 확인 항목으로.
8. **AI 생성 금지 대상** — 실제 관측 결과 흉내·실존 시설·실존 인물·실물 디자인·기업 로고·특정 도시·숫자 혼동 프레임.
9. **이 문서를 쓰는 곳** — 스토리보드 근거 칸, 자막 표기 통일, 제작안 승인 때 제시.
10. (추가) **인용의 원문 사슬** — 기사 번역 인용이면 원 기관 영문 원문을 찾아 붙인다 (ESO 보도자료 등, 라이선스 확인).

## 대조 규칙

- ✅ = 기사와 일치 / ⚠️ = 축약·조건 생략·내역 불일치 등 화면 처리 필요 / — = 대본 미사용.
- 직접인용(큰따옴표)은 **원문 그대로만**. 축약문에 따옴표 금지. 카드가 길어 못 읽으면 줄바꿈·노출 시간으로 풀지 문장을 줄이지 않는다.
- 합계와 내역이 어긋나면(대본이 일부 생략) 화면엔 합계만, 내역 그래픽 금지.
- 조건부 사실("반사광 안에서 보면 4배")은 조건 문구를 화면에 같이.
- 같은 숫자가 다른 뜻으로 두 번 나오면(10만 계획 vs 10만 한계선) 한 프레임에 두지 않는다.

## output에 회신할 때

규칙 번호로 답한다: "b10 — facts #11 조건 문구 누락", "b17 — #25 인과 화살표 금지". 맞는 것도 번호로 확인해 준다.
