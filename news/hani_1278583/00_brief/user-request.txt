아래 기사로 세로 숏폼 뉴스 한 편을 처음부터 끝까지 제작해줘.
기사:  https://www.hani.co.kr/arti/science/science_general/1278583.html
분량·독자: 60~90초, 일반 비전공 시청자.

이 프로젝트의 config/production-engine.json이 선택한 editorial-concept@1 엔진과 config/production-defaults.md의 제작 기본값을 사용해. 자막은 config/production-profile.json의 betelgeuse-v1 프리셋, 로고는 presets/hani/brand-assets/v1/manifest.json, 썸네일은 presets/hani/thumbnail-fixed(또는 thumbnail-flexible) 프리셋을 적용해. 루트 CLAUDE.md, docs/PRODUCTION_PROMPT_V2_RESTORED.txt 전문, plugin/skills/shortform-news-pipeline/SKILL.md와 reference/production-entry.md·visual-production.md·visual-references.md를 읽고, `npm run produce -- start <id> --url <기사 URL> --duration 60:90 --request-file <요청 원문>`로 이번 기사에 새 편 ID를 만들어 시작해. 기존 experiments/·internal/·references/의 시험 편은 기술 시험이므로 제작 소재나 품질 참고로 사용하지 마. 원래 운영 프로젝트의 기본 엔진·설정은 유지해.

목표는 기사에 맞는 미술·설명·모션으로 완성 영상을 만드는 것이야. start가 반환하는 context.reference_library(references/visual/README.md·collection.json과 cases/*/versions/v1의 final.mp4·walkthrough.md·source/entry.tsx·timing.json)를 연출 설계 전에 모두 확인하고, reference/visual-references.md대로 이번 편에 실제로 가져올 판단 한둘을 사례 출처와 함께 제작 노트에 남겨. 레퍼런스의 정보 위계, 시선 유도와 맥락, 원인-작용-결과, 실사 합성, 발화와 움직임의 연결을 이번 기사에 맞게 적용하고, 도해에서도 조형 완성도가 이어지게 해줘. 설명이 진행되면 처음 보던 대상에서 다음 대상·관계로 시선이 이어지게 하고, 무음으로도 핵심 대상·작용·결과가 어느 정도 읽히게 해줘. 같은 대상을 유지하면서 구도·거리·가림·공간은 기사에 맞게 바꿀 수 있어. 상단에 고정 제목·장면명·제작 주석을 추가하지 말고, 필요한 조건·귀속은 관련 대상·수치 곁이나 자막에 붙여줘. 예측·가정·불확실성을 지우지 않으면서 제목·자막·주석으로 같은 설명을 겹치지 말고, 첫 관심이 마지막 이해로 이어지도록 내용을 선택해줘.

한 제작자가 원고·자료·생성·합성·편집·음향을 함께 판단해. 장면 수·순서·구도·구현 수단과 필요한 수정은 위임할게. 장면별 중간 승인을 추가하지 마. 기사 본문과 필요한 1차 근거·고유 대상의 형태를 확인하고, 그 범위에서 외부 검색과 자료 확보를 진행해(CLAUDE.md의 사전 승인된 subagent source-verify·sourcing·editorial-judge·shot-judge·fact-check는 정해진 위치에서 호출해). 기사에 있는 계획·예측·조건을 이미 실현된 사실처럼 바꾸지 마.

이미지·영상 생성은 Higgsfield MCP(mcp__claude_ai_higgsfield__generate_image/generate_video), 내레이션은 Typecast(불가 시 Higgsfield generate_audio)를 사용해. 실제 생성·TTS·렌더와 필요한 수정을 진행해. Higgsfield 생성은 실제 호스트 도구로 호출한 뒤 visual-system.generation_jobs와 media.assets[].generation_job에 기록하고, 음성 생성은 `npm run produce -- begin <id> narration --tool <도구명>` → 실행 → `finish <id> <token>`으로 기록해. 최종 조립은 `npm run produce -- run <id> render`로 실제 음성·자막 시간(narration.json → timeline → sync)을 연결해. 낭독 원문·실제 사용한 음성·자막·화면 편집 시간을 함께 갱신해. 화면 편집 코드는 src/editorial/episodes/<id>.tsx에 자유롭게 작성하고, 레퍼런스 사례나 과거 기사 영상·편집 코드를 새 편의 내용으로 재사용하지 마. 자막의 위치·서체·크기·색·검은바·줄 수는 config/production-profile.json의 동결 프리셋을 적용하고, 주요 행동이 그 구역에 가리지 않게 화면을 설계해. 수령 로고 presets/hani/brand-assets/v1은 start가 편별로 연결하고 공통 화면이 동결된 배치대로 합성하므로 생성물이나 장면 코드에 중복 삽입하지 마. 실제 로고 위치에 주요 대상·자막이 가려지지 않는지 확인해. 별도 인트로·아웃트로나 자체 제작 로고를 추가하지 마.

첫 전체 시안부터 작은 시청 크기에서 레퍼런스 사례와 비교해 이야기의 집중, 미술 수준의 일관성, 정보 위계, 설명에 따른 시선 이동, 실제 행동과 리듬을 확인해줘. 독립 시각·음성·사실 검수(shot-judge·fact-check, review_visual/review_audio/review_facts — intent 대조에는 같은 레퍼런스 세트와 이번 편의 적용 판단을 함께 붙여)를 받고 약한 부분은 자산·구도·길이·원고·TTS까지 필요한 만큼 수정해. 기술 검사 통과를 레퍼런스 재현 성공으로 기록하지 마. 프레임 관찰·연속 시청·직접 청취를 구분하고 실제 확인하지 못한 범위는 미확인으로 남겨. 확인 가능한 작업과 수정은 끝까지 수행해.

첫 전체 시안과 최종본, 원문·사실 근거·원고·자막·생성 원본·실제 프롬프트와 참조 입력·재실행 방법을 news/<id>/ 아래(01_input 원본 보존, 02_production 파생물)에 보존해. 검수와 수정은 reference/review-loop.md의 `review-template` → `begin <id> review_visual --output …/reviews/*.json` → `finish`, `resolve <id> <receipt:이슈id> --reason …`, `complete <id>` 경로로 연결하되 실제 근거가 없는 pass나 완료를 만들지 마. 완료 조건이 남아도 만들어진 최종 시안과 남은 한계를 제출해.

마지막에는 첫 시안과 최종 MP4의 정확한 경로(out/pilots/<id>/…)를 알려주고, news/<id>/02_production/RESULTS.md에 적용한 참고, 주요 수정과 이유, 확인 범위, 레퍼런스 사례 대비 남은 차이, 걸린 시간·실제 생성 횟수·확인 가능한 비용(Higgsfield balance/transactions)을 간단히 정리해줘. 첫 시안과 최종이 같다면 그대로 밝혀줘. 별도 승인 대기 없이 제작과 가능한 검수·수정까지 진행해.

전체 제작 산출물에 이야기·편집 효과음과 같은 기사의 썸네일을 포함해. 음향·썸네일 작업 때 reference/rules-finish.md(§10 D 오디오·§12 커버)와 cover.md·cover-style.md·cover-build.md를 읽고, 사용 근거·실제 입력·검수 범위를 cover-record.json과 함께 제출해. 썸네일만 수정할 때 영상 제작을 다시 시작하지 마.
